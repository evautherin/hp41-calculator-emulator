# help-aliases

Dev-only generator for HP-41 calculator help function search aliases.

## Purpose

Populates the `search_aliases` field in all six HP-41 help JSON pools
(`docs/hp41-*-functions.json`) with DE+EN search terms generated by an LLM.
The aliases enable bilingual (German + English) full-text search in the
calculator's `?` help overlay.

## Usage

```sh
just help-aliases
```

This runs the generator over all six pools in sequence. Each pool is processed
in-place: the file is read, aliases are appended to eligible entries, and the
file is written back with a minimal diff (only `search_aliases` arrays are added).

To process a single pool manually:

```sh
cargo run --manifest-path scripts/help-aliases/Cargo.toml -- docs/hp41cv-functions.json
```

## Re-run Policy

**Re-run only when functions are added or their semantics change.**

The generator uses fill-only semantics (D-60.2): it only populates `search_aliases`
for entries that have no aliases yet. Entries that already have aliases are left
byte-for-byte untouched, protecting any hand-curated entries from accidental
overwrite.

Because the generated aliases are committed as static, PR-reviewable data, there
is no need to regenerate them on every build or CI run. The committed aliases are
the source of truth — they are not regenerated automatically.

Reasons to re-run:
- A new `status:"implemented"` function was added to a pool.
- An existing function's description or semantics changed significantly.
- You want to improve aliases for a specific category (delete its `search_aliases`
  field first so the fill-only logic picks it up again).

## Fill-only Behavior

The generator:
- Processes only entries with `"status": "implemented"`.
- Skips any entry whose `search_aliases` is already a non-empty array.
- Appends `search_aliases` as the last key in each updated entry.
- Preserves all existing key order, UTF-8 characters, and formatting in the rest
  of the file (D-60.4 minimal-diff writeback).

A per-pool run summary is printed to stdout:
```
docs/hp41cv-functions.json: 154 scanned, 18 skipped, 136 populated, 816 aliases added
```

## Authoring-time-only Guarantee

The `claude` CLI dependency lives only inside this crate. It is never invoked
during a normal build, CI run, or runtime execution of the HP-41 emulator.
The `scripts/help-aliases/` directory carries an empty `[workspace]` stanza
in its `Cargo.toml`, which excludes it from the root workspace — so `cargo build`
at the project root never touches this crate (D-60.6 / HSGEN-02).

The LLM is an **authoring tool**, not a runtime component. The shipped binaries
(`hp41-cli`, `hp41-gui`) only `include_str!` / import the **static JSON** files
containing the committed aliases.

## PR Review

Alias additions are committed as a regular diff in the PR. The minimal-diff
writeback ensures only the `search_aliases` arrays are changed — all other
fields and their ordering remain identical to the pre-existing file.

Review the aliases for quality (are the DE and EN terms useful search keywords?)
and reject any that are misleading or would surface the wrong function.
