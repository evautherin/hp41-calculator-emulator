# ADR v4.3-006: Authentic 12-Cell LCD Rendering for Scientific Overflow

**Status:** Accepted
**Date:** 2026-06-07
**Phase:** 65 (standalone-fidelity-fixes — UAT follow-up)

## Context

ADR v4.3-005 extended `HpNum` so `FACT(27..=69)` returns real factorials instead of
`Overflow`. This made large magnitudes (e.g. `FACT(27) = 1.088886945E28`,
`FACT(69) = 1.711224524E98`) reachable in the GUI for the first time.

The GUI 14-segment display (`hp41-gui/src/Display14Seg.tsx`) has exactly **12 character
cells** and silently truncates anything longer (`Display14Seg.tsx:212`). The canonical
formatter `format_hpnum` emits scientific notation as `{mantissa}E {exp}` — e.g.
`1.088886945E 28`, which is **14 cells** (the decimal point folds into its digit). The
extra `E` + separating space pushed the exponent off the right edge: the GUI showed
`1.088886945E` with the exponent **truncated**, while the (wide) stack panel showed the
full `…E 28`. UAT caught this on `FACT(27)`.

The real HP-41C 12-character LCD shows scientific notation **without an "E"**: the
exponent is right-justified in the rightmost cells (a leading `-` only when negative),
the mantissa is left-justified, and any slack between them is blank.

## Decision

Add `format_hpnum_lcd(n, mode)` in `hp41-core/src/format.rs` and use it for the GUI
main-display X branch (`types.rs::from_state` `display_str`). It reflows **only** when
`format_hpnum`'s output exceeds 12 cells:

- **≤ 12 cells** (all FIX values, SCI/ENG with small exponents) → returned unchanged, so
  existing rendering — including the `E` form for short scientific output — is preserved.
- **> 12 cells** → drop the `E`, right-justify the exponent, keep as much mantissa
  precision as fits:
  - positive exponent → up to 10 significant digits + 2 exponent digits = 12 cells;
  - negative exponent → mantissa + `-` + 2 exponent digits = 12 cells (the sign reserves
    one mantissa cell, so the mantissa drops to 9 significant digits).

The shared rounding/carry logic is factored into `round_sci_parts`, used by both
`format_sci_large` (the wide `E` form) and `format_hpnum_lcd`.

### Display variant chosen (UAT decision, 2026-06-07)

Right-justified exponent (hardware-faithful). For the full 10-digit mantissa of a
positive-exponent factorial the mantissa and exponent butt together flush (no gap):

```
FACT(27)  1.08888694528   (mantissa 1.088886945 + exponent 28, 12 cells)
FACT(69)  1.71122452498
1.23e-50  1.23456789-50    (negative: 9-digit mantissa + signed exponent)
```

## Scope

- **GUI only.** The CLI status/stack display and the GUI stack panel (`x_str`/`y_str`/…)
  keep the wide `format_hpnum` `E` form — they are not constrained to 12 cells. This is a
  deliberate scope limit, not a parity violation (D-25.6 governs SHIFT/keyboard state, not
  display width).
- **VIEW of a huge register** writes its string into `display_override` in core
  (`op_view`) and flows through a different branch; reformatting that override is out of
  scope for this ADR (edge case, not the reported X-display bug).

## Consequences

- `FACT(27..=69)` and any scientific overflow now display in full on the GUI's 12-cell LCD.
- Tight positive-exponent output (`1.08888694528`) has no visual gap between mantissa and
  exponent — accepted as the hardware-faithful behavior.
- Tests: `hp41-core/tests/phase65_lcd_display.rs` (12-cell guarantee, no-`E`, negative
  exponent, delegate path) + `types.rs` GUI `from_state` test.
