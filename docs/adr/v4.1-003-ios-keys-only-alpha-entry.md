# ADR v4.1-003 — iOS ALPHA Entry: Native On-Screen Keys Only (supersedes TOUCH-04)

**Status:** Accepted
**Date:** 2026-06-03
**Context:** v4.1 iOS Foundation — post-Phase-55 on-device polish (quick tasks 260603-sef, 260603-u6t)

## Context

Phase 55 (TOUCH-04) gave iOS ALPHA-register and "FUNCTION NAME?" text entry a
software-keyboard affordance: an `AlphaTouchInput` bar that `autoFocus`-es a hidden
`<input>` to pop the iOS keyboard, dispatching each typed character as `alpha_<X>` (or
accumulating a modal label). On-device testing in this milestone surfaced that this
approach fights the HP-41 mental model and the app's own layout:

- The bar is `position: fixed` but rendered inside the calculator's `transform: scale()`
  container, so a transform ancestor became its containing block — it was glued to the
  scaled calculator's bottom edge and overlapped the keypad (the same trap the PRGM sheet
  had). Portaling it to `document.body` (260603-sef) fixed positioning but exposed further
  issues: the field cleared after each keystroke (looked empty), the Done button was
  clipped, and — critically — the field could not reflect text typed via the on-screen
  HP-41 keys (it only captured the iOS soft keyboard).
- The owner's decision: ALPHA entry should be **native HP-41 — the on-screen blue-letter
  keys only**, with no iOS software keyboard anywhere, matching the real calculator.

## Decision

**Remove the iOS software-keyboard ALPHA affordance entirely. ALPHA-register and
"FUNCTION NAME?" entry on iOS use only the on-screen HP-41 keypad.**

- The `AlphaTouchInput` bar (and its keyboard pop) is no longer rendered — neither for
  plain ALPHA-register mode nor for the INTG/SOLVE/DIFEQ `FUNCTION NAME?` modal-label
  prompt. (`AlphaTouchInput.tsx` becomes dead code, pending a cleanup pass.)
- The on-screen keys already dispatch `alpha_<X>` in ALPHA mode (`handleClick`: `alphaOn &&
  key.alphaChar`). The typed ALPHA text is shown on the **main 14-segment display**
  (`display_str = format_alpha`), exactly as on hardware.
- The on-screen **← key** (`clx_or_a`) in ALPHA mode now dispatches **`alpha_backspace`**
  (`Op::AlphaBackspace`, delete last char) instead of `alpha_clear` (full wipe). Full clear
  remains available via `XEQ "CLA"`.
- The **physical Backspace** key in ALPHA mode dispatches `alpha_backspace` (was
  `entry_backspace`, which clears the number-entry buffer) — fixing desktop ALPHA deletion
  and matching the CLI's `handle_alpha_mode_key` (D-13). CLI↔GUI parity (D-25.6) restored
  on this point.
- The `FUNCTION NAME?` prompt is spelled with the on-screen keys via the existing
  collect-for-modal `pendingInput` path: blue-key letters accumulate into the name and
  ALPHA submits through the magic-prefix bridge `__submit_modal_with_label__<acc>` →
  `invokeForKey` → the **same** `submit_modal_with_label` Tauri command the bar used. No
  backend change; the keys path was already wired (Phase 31 design, mirrors the CLI
  CollectForModal).
- **iOS touch targets are sized to the actual key** (`keyPosition()` width/height), not a
  fixed 44px centered dot. The wide ENTER key (`colSpan: 2`) previously had only a 44px
  centre target, which made its ALPHA letter `N` nearly un-tappable once entry went
  keys-only. CSS `min-width/height: 44px` keeps small keys HIG-compliant.

## Consequences

- **Authentic + simpler:** no iOS keyboard, no `position: fixed`-in-transform bar, no
  controlled-input/async-mirror complexity. ALPHA text lives only on the main display, as
  on hardware.
- **Supersedes TOUCH-04:** the Phase-55 decision to provide an iOS-keyboard ALPHA bar is
  reversed. The Phase-55 ALPHA touch-input work and the 260603-sef ALPHA-bar refinements
  (mirror, min-width, themed Done) are obsoleted by removal; the sef **print-sheet portal**
  remains valid.
- **Desktop unchanged** except the Backspace-in-ALPHA fix (now deletes the last ALPHA char,
  as it always should have).
- **Known divergence (accepted, carried forward):** ALPHA overrides SHIFT on the on-screen
  keypad. See `docs/hp41cv-divergences.md`.
- **Follow-up:** delete the now-unused `AlphaTouchInput.tsx` + `.alpha-touch-input-bar` CSS.
