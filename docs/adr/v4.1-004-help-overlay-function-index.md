# ADR v4.1-004 — Help Overlay: Tabbed Full-Function Index + Tap-to-Run (revises D-26.8)

**Status:** Accepted
**Date:** 2026-06-03
**Context:** v4.1 iOS Foundation — quick tasks 260603-lu0, 260603-s17, 260603-scc

## Context

The `?` help overlay (Phase 26, D-26.8) rendered only functions with a `key_path` — i.e.
keyboard-reachable ones — via `helpEntriesAll().filter(e => e.key_path !== null)`. On-device
a user asked "where do I find CLRG / CLST?" An audit found the overlay was effectively a
*keyboard-shortcut* cheat-sheet, not a function index: **74 implemented HP-41CV built-ins
with `key_path: null`** (CLST, CLA, AVIEW, SIZE, the trig/math functions, …) were invisible
and unsearchable. Two adjacent fidelity problems surfaced: the engine spelled "clear
registers" as the non-authentic `CLREG` (the real mnemonic is `CLRG`), and the function
matrix carried other inauthentic mnemonics (`CL SIGMA` for `CLΣ`) plus a duplicate
(`CLRALPHA` vs `CLA`).

A further problem, specific to iOS: even when listed, the keyless functions are hard to
*invoke* — XEQ-by-name via the on-screen keys requires knowing the opaque key→letter
mapping.

## Decision

**Revise D-26.8: the `?` overlay becomes a tabbed function reference, and its "All
Functions" entries are tappable to run.**

1. **Two tabs.** "Keyboard Shortcuts" keeps the original `key_path !== null` view. "All
   Functions" lists **every `status: "implemented"` entry across all 6 JSON pools**,
   grouped **Module → Category** (HP-41CV Built-in → Math 1 → Stat 1 → Time → Advantage
   [single header] → Extended Memory). Default tab: iOS → "All Functions", desktop →
   "Keyboard Shortcuts". Search applies within the active tab.
2. **Tap-to-run (D-lu0-02).** Each runnable "All Functions" row is a button: tap dispatches
   `xeq_<display_name>` (`Op::Xeq` via the existing resolver), executing the function — or,
   in PRGM mode, inserting it as a program step (the engine's `dispatch()` PRGM gate). 303
   of 364 implemented entries are directly runnable (their `display_name` is the exact
   resolver mnemonic — no JSON schema change). The 61 that are NOT XEQ-runnable
   (parameterized STO/RCL/FIX/…+IND, immediate keys `+ − × ÷ ENTER …`, mode/composite rows)
   render non-tappable and are never dispatched (D-07, never swallow an unresolvable id).
   The 61-op `NON_TAPPABLE` set is pinned in both TS and a Rust drift guard
   (`tappability_parity.rs`).
3. **Mnemonic fidelity (260603-s17).** `CLREG` → authentic `CLRG` (with `CLREG` kept as a
   back-compat XEQ alias; `Op::Clreg` variant unchanged for save-file compat).
   `CL SIGMA` → `CLΣ` (the resolver + both `op_display_name` mirrors already used the glyph;
   data-only change). `CLRALPHA` (`Op::AlphaClear`, the v1.0 legacy alias of `Op::Cla` =
   `CLA`) stays resolvable + in the enum for v1.0 save-file compat (Pitfall 8) but is hidden
   from the index via `OVERLAY_HIDDEN_ALIASES`, so `CLA` shows once.
4. **CLI parity (260603-scc).** The CLI `?` overlay already listed all pools; keyless
   built-ins now show `XEQ "NAME"` in the key column (the CLI analog of tap-to-run) and
   deferred-v3 entries are filtered out, mirroring the GUI's `allFunctionsEntries()`.
5. **Guardrails.** A Vitest test asserts every implemented function appears in the
   "All Functions" dataset (so none can be silently re-hidden); a Rust test asserts every
   runnable `display_name` resolves; a CLI test mirrors the completeness check.

## Consequences

- The original discoverability gap is closed: all 74 keyless built-ins are findable and,
  where runnable, tappable. CLRG/CLST/SIN/AVIEW etc. are now reachable by name + tap.
- `XEQ "CLRG"` and `XEQ "CLΣ"` now resolve (authentic mnemonics); `XEQ "CLREG"` /
  `"CL SIGMA"` kept as back-compat aliases.
- No `hp41-core` op/algorithm change; no Op enum change (4-way invariant untouched). JSON
  canonical data flow honored (`just docs-matrix` regenerated; `docs-matrix-check` green).
- Visual styling of the All-Functions tab was brought to the HP-41 look (opaque overlay,
  segmented tabs, themed tappable rows) after on-device feedback.
- **Deferred follow-ups:** sibling-mnemonic audit beyond CLΣ/CLRALPHA; optional CLI
  module-section headers; `CLST` authenticity (the real HP-41 lacks a single clear-stack op
  — out of scope).
