# ADR v4.3-002 — macOS Global Hotkey for the Menu-Bar Popover

**Status:** Accepted
**Date:** 2026-06-06
**Context:** Post-v4.2 desktop polish (user request: open the menu-bar app via a keyboard shortcut)

## Context

The menu-bar app (ADR-v4.1-001) can only be toggled by left-clicking the tray icon.
The user asked for a system-wide keyboard shortcut to show/hide it, and for that
shortcut to be configurable.

## Decision

Add a **macOS-only, user-configurable** global hotkey (default `⌃⌥⌘H`) that toggles the
menu-bar popover.

- **Plugin:** `tauri-plugin-global-shortcut`, dependency gated to
  `cfg(target_os = "macos")`. On macOS it uses Carbon `RegisterEventHotKey`, so it needs
  **no** Accessibility / Input-Monitoring permission.
- **Shared toggle:** the tray click, the hotkey handler, and the single-instance
  re-launch (ADR-v4.3-001) all funnel through one `tray::toggle_popover` /
  `tray::surface_popover`. To position the popover when there is no fresh tray event,
  `PopoverState` gained `last_tray_rect` (captured on every tray click); callers fall
  back to a top-right anchor (`compute_fallback_position`, unit-tested) before the first
  click.
- **Configurable, backend-validated:** the accelerator lives in
  `GuiPrefs.global_shortcut` (`#[serde(default)]` → `DEFAULT_GLOBAL_SHORTCUT`,
  back-compat preserved). A Settings-panel recorder (`ShortcutRecorder.tsx`, macOS-gated
  like the launch-mode radio) captures a combo as a Tauri accelerator string and persists
  it through the existing `set_pref` command. The **Rust side is the validator**:
  `set_pref` parses + live-re-registers the accelerator and returns `Err` for an
  unparseable value, so only an accepted hotkey is reflected back into the UI. Startup
  registration (`shortcut::install`) falls back to the default for any non-empty-but-
  unparseable stored value.
- Only one hotkey is ever registered, so the plugin handler toggles unconditionally on
  `ShortcutState::Pressed` without matching a specific `Shortcut`.

The accelerator literal has a single source of truth: `prefs::DEFAULT_GLOBAL_SHORTCUT`,
re-exported by the macOS `shortcut` module.

## Consequences

- New GUI-workspace runtime dependency: `tauri-plugin-global-shortcut` (macOS target
  only). `hp41-core` "zero new runtime deps" invariant untouched.
- **No new Tauri command / capability:** registration happens entirely in Rust; the
  recorder is pure JS keydown capture feeding the existing `set_pref` — so
  `capabilities/default.json` and the permission-coverage gate are unchanged.
- The hotkey also works in "window" launch mode (acts as a summon shortcut), since
  `toggle_popover` operates on the main window regardless of mode.
- `prefs.rs` stays platform-neutral: it cannot parse accelerators (the `Shortcut` type is
  macOS-only), so it only repairs an *empty* stored value; full validation is the macOS
  `shortcut` module's job. iOS build unaffected (verified by
  `cargo check --target aarch64-apple-ios`).

## Alternatives considered

- **JS-side `@tauri-apps/plugin-global-shortcut`** — rejected: would need a frontend
  capability and duplicate the toggle logic in TS; Rust registration keeps one toggle
  path and no capability surface.
- **Hardcoded, non-configurable hotkey** — rejected: the user explicitly asked for
  configurability; the recorder reuses the established Settings-panel + `set_pref` pattern.
- **Frontend-only validation of the accelerator** — rejected: the backend must register
  it anyway, so making Rust the single validator avoids drift between the TS recorder's
  token format and the parser.
