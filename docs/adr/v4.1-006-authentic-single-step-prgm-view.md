# ADR v4.1-006 — Authentic Single-Step PRGM View (restores CLI↔GUI display parity)

**Status:** Accepted
**Date:** 2026-06-03
**Context:** v4.1 iOS Foundation — quick task 260603-o2e

## Context

In PRGM mode the GUI rendered a **multi-line program listing** — an iOS `BottomSheet`
("PROGRAM") and a desktop `.prgm-panel`, both showing `program_steps`. On the real
HP-41C/CV there is no listing: the single LCD shows **one program step at a time** (e.g.
`001 XEQ CLRG`), navigated with SST/BST. The listing also caused an iOS layout problem (the
`position: fixed` PRGM sheet overlapped the keypad).

A second issue surfaced during the keys-only work: the GUI's `CalcStateView::from_state`
display-priority chain had **no `prgm_mode` branch**, so in PRGM mode the main display
showed the X register instead of the current step. The CLI (`ui.rs`) already did the
authentic thing — a CLI↔GUI parity (D-25.6) divergence. `format_step()` existed in the GUI's
`prgm_display.rs` but was annotated `#[allow(dead_code)]` (unused).

## Decision

**Make the GUI PRGM view authentic: the main display shows the current step; remove the
program listing on both platforms.**

1. **Backend (the load-bearing change):** add a `prgm_mode` branch to the GUI's
   `CalcStateView::from_state` display-priority chain (`prgm_display::format_step(state)`),
   placed to mirror the CLI's order (clock → stopwatch → entry_buf → **prgm_mode** → alpha →
   X). Removed `#[allow(dead_code)]` from `format_step`. No new `Op` variant → the 4-way
   exhaustive-match invariant is untouched; this is GUI `src-tauri`, not `hp41-core`.
2. **Frontend (deletion):** remove the iOS `prgm-sheet` `BottomSheet` AND the desktop
   `.prgm-panel`, plus `activeStepRef`, the pc-scroll effect, and the prgm dep on the
   recompute trigger. Navigation is SST/BST, which already update `pc`; the new step shows
   in the main display via the same IPC response. The print sheet is untouched;
   `program_steps`/`pc` stay in the IPC contract (unused by the UI now — removal deferred).

## Consequences

- PRGM mode is hardware-authentic: one step in the LCD, SST/BST to navigate; no listing.
- **Restores CLI↔GUI parity (D-25.6)** on the display-priority chain.
- The iOS PRGM-sheet overlap problem is eliminated by removal (no sheet).
- Pairs with tap-to-run (ADR v4.1-004): tapping a function in the help overlay while in PRGM
  mode inserts an `XEQ <NAME>` step, visible immediately in the authentic single-step display.
