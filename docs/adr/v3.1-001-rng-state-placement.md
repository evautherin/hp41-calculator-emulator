# ADR-v3.1-001: RNG State Placement — `rand_seed: HpNum` on `CalcState` with `#[serde(default)]` WITHOUT `#[serde(skip)]`

**Status:** Locked 2026-05-22
**Owner:** Plan 33-01 + Plan 33-08
**Requirement refs:** STAT-RNG-01, STAT-RNG-02, STAT-RNG-03, STAT-RNG-04, Pitfall 20 (33-RESEARCH.md §"RNG serde — `serde(default)` vs `serde(skip)` muscle-memory trap")
**Downstream consumer:** `hp41-core/src/state.rs:201-202` (`rand_seed: HpNum` field with the unique serde shape); `hp41-core/src/ops/stat1/rand.rs` (`op_rand`, `op_seed` — LCG implementation per Plan 33-08); `hp41-core/src/state.rs:721` (`rand_seed_serde_round_trip` test — CI guard)
**ADR write-up prose:** Phase 35 / STAT-DOC-04 (this is the narrative ADR; the lock happened during Phase 33 discuss-phase 2026-05-22 / D-33.4)

---

## Context

HP-41C Stat 1 Pac (HP 00041-90030, 1979) does not list `RAND` or `SEED` as
top-level XROM entry points in its Quick Reference Card or Owner's Manual mnemonic
table. The Stat 1 Pac OM is silent on a random-number facility: the program suite
ends at ΣCHISQD, ΣTSTAT, and ΣSPEAR without a SEED-prompt / RAND-XEQ pair. Yet
three independent community sources document the LCG formula that the HP-41C
ecosystem treats as "the Stat 1 Pac RNG":

- Naval Postgraduate School technical note NPS55-84-003 (Zehna, 1984, DTIC
  AD-A140573), pages 21–22, describes the LCG `r_{n+1} = FRC(9821·r_n + 0.211327)`
  as the canonical HP-41 RNG and uses it in the `ZP4` program convention to
  prompt for a SEED via ALPHA-mode entry.[^2]
- The HP-65 User's Library entry attributed to Don Malm provides the same LCG
  coefficients (9821 and 0.211327) as historical community convention.[^3]
- HP-41C Standard Applications (1979), page 24, gives the LCG as a secondary
  source independent of the Stat 1 Pac OM itself.[^4]

The v3.1 milestone therefore ships RAND / SEED as an **emulator extension** —
distinct from the OM-feature-complete claim — under requirements STAT-RNG-01..04.
The user-visible contract is: `XEQ "SEED"` opens an ALPHA prompt that captures the
initial seed; subsequent `XEQ "RAND"` calls advance the LCG and push the result onto
the stack. The reproducibility promise (STAT-RNG-03) is that a user who calls SEED
in session A, saves, reopens session B, and calls RAND must observe the same
sequence she would have observed had session A continued uninterrupted.

That promise puts the seed at odds with v1.0–v3.0's transient-field
convention. The frozen-invariant rule in `CLAUDE.md §"Save-file backward compat"`
states: every new `CalcState` field carries `#[serde(default)]`; transient fields
**additionally** carry `#[serde(skip)]`. Every other `#[serde(default)]` field in
v3.1's enlarged `CalcState` (`print_buffer`, `modal_program`, `modal_prompt`,
`integ_state`, `solve_state`, `difeq_state`, `cancel_requested`) carries
`#[serde(skip)]` because none survives session boundaries. The RAND seed is the
exception: it must persist so SEED-driven reproducibility holds across saves, yet
it cannot break the v1.0–v3.0 load path either — old save files (which have no
`rand_seed` key at all) must continue to deserialize without manual migration
(Pitfall 24, save-file backward compat).

The trap Pitfall 20 catalogues is the muscle-memory failure mode: a future
maintainer skims the `CalcState` struct, sees twenty `#[serde(default, skip)]`
attributes in a row, and "fixes" `rand_seed` to match — silently breaking
STAT-RNG-03. The placement and serde-shape choice therefore deserves a long-form
ADR rather than a one-line comment.

---

## Decision

**`rand_seed: HpNum` is declared on `CalcState` with `#[serde(default)]` ONLY —
NOT `#[serde(skip)]`.** The default value is `HpNum::zero()`.

The serde shape is unique to this field within v3.1 (the existing v3.0 sibling
that shares the shape — `complex_mode: bool` — predates the convention sweep).
The field is initialised by `XEQ "SEED" <alpha-seed>` (STAT-RNG-02), advanced on
every `XEQ "RAND"` call via the LCG (STAT-RNG-01), and serialised to
`~/.hp41/autosave.json` on every 30-second auto-save tick (shared by CLI + GUI
per CLAUDE.md `### GUI specifics → Persistence sharing`).

Backward compatibility with v1.0–v3.0 save files is preserved by `serde(default)`
itself: when an old save file is deserialised, the absent `rand_seed` key falls
through to `HpNum::zero()`. The first `XEQ "RAND"` from a zero seed evaluates
`FRC(9821·0 + 0.211327) = 0.211327` — the IN-05 behaviour documented in
33-REVIEW.md and routed to `docs/hp41-stat1-divergences.md` (D-35-12 or sibling)
during Plan 35-02. The choice to start from `HpNum::zero()` rather than from a
hardcoded "factory seed" is deliberate: the Stat 1 Pac OM specifies nothing about
default seed state, so picking a non-zero default would itself be a divergence
without provenance. Zero is the only defensible default.

The block-the-PR rule lives inline at `state.rs:198-200`: any future edit
that adds `#[serde(skip)]` to this annotation is a STAT-RNG-03 contract violation.
The CI guard is `rand_seed_serde_round_trip` at `state.rs:721`, which constructs
a `CalcState` with a non-zero seed, round-trips through `serde_json::to_string` /
`from_str`, and asserts that the seed survives.

```rust
// hp41-core/src/state.rs (lines 175–202)
//
// rand_seed: HpNum — Stat 1 Pac RAND/SEED LCG state (D-33.4 / ADR-v3.1-001).
//
// Source: NPS55-84-003 (Zehna, 1984), p. 21–22 — LCG formula
//   r_{n+1} = FRC(9821 · r_n + 0.211327)

//
// ⚠️ UNIQUE SERDE SHAPE — the SOLE new v3.1 CalcState field that
// carries #[serde(default)] WITHOUT #[serde(skip)]. The seed MUST
// survive save/load so program-driven SEED commands persist across
// sessions and RAND determinism is preserved (STAT-RNG-03).
//
// Mirror pattern: complex_mode: bool above is the IDENTICAL
// #[serde(default)] (no skip) shape — the ONLY existing precedent

// (print_buffer / modal_program / modal_prompt / integ_state /
//  solve_state / difeq_state / cancel_requested) ALSO carries
// #[serde(skip)] — DO NOT mimic those for this field.
//
// Code review block-the-PR rule: any future edit adding skip to this
// annotation is a STAT-RNG-03 contract violation. The
// rand_seed_serde_round_trip test in mod tests is the CI guard.
#[serde(default)]
pub rand_seed: HpNum,
```

## Consequences

### Positive

- **Reproducible simulations across save/load cycles (STAT-RNG-03).** A program
  that calls `SEED 0.5` and `RAND` once produces the same sequence after a save
  and reload as it would have produced in an uninterrupted session.
- **v1.0–v3.0 backward compat preserved.** Old save files load via the
  `serde(default)` fallback (`rand_seed = HpNum::zero()`); no migration step,
  no version bump in the JSON payload.
- **Pitfall 20 muscle-memory trap mitigated.** Every other v3.1 `CalcState`
  field follows the standard `#[serde(default, skip)]` pattern; `rand_seed` is
  the documented exception with an inline block-the-PR comment and a dedicated
  CI guard test.
- **Single source of truth.** `state.rs:201-202` is the only place the serde
  annotation lives; `migrate_after_load()` does not touch the seed (no mutation
  on load), which keeps D-33.7's idempotent-migration invariant intact.

### Negative

- **IN-05 first-call-from-zero behaviour is potentially surprising.** A user who
  never calls SEED but calls RAND repeatedly observes a deterministic sequence
  starting from `FRC(0 + 0.211327) = 0.211327`. The behaviour is correct under
  the LCG formula but may astonish a user expecting "random-looking" output on
  the first call. Mitigated by routing the note to D-35-12 in
  `docs/hp41-stat1-divergences.md` (Plan 35-02) where the catalog explains the
  zero-default rationale and the LCG's zero-seed fixpoint.
- **Special-case in the otherwise-uniform serde sweep.** Anyone reviewing
  `CalcState` for the first time must understand why this one field breaks the
  pattern. Mitigated by the 25-line documentation comment immediately above the
  field declaration (`state.rs:175-200`).

### Neutral

- The `state.rs:201-202` line range is the canonical reference for the serde
  shape; future ADRs that touch persistence cite this anchor.
- The field-level CI guard `rand_seed_serde_round_trip` at `state.rs:721` is
  the single test required to defend this invariant — it is small, fast, and
  has zero external dependencies.
- Future v3.2+ pacs that need persistent-across-sessions state (e.g. a Time
  Pac that needs a wall-clock-offset baseline) inherit this pattern: add a
  field with `#[serde(default)]` only, document the exception inline, and add
  a serde round-trip test next to the field.

## Alternatives Considered

### Option B: `#[serde(skip)]` on `rand_seed` (always reset to zero on load)

The rejected alternative is described verbatim in 33-CONTEXT.md D-33.4 (locked
2026-05-22):

> **D-33.4:** If `/gsd-spec-phase 33` OM read shows RAND is NOT a top-level
> Stat 1 Pac ROM entry point, implement RAND / SEED anyway as a v3.1 emulator
> extension (STAT-RNG-01..04 already drafts the requirements that way).
> Justification:
>   - STAT-RNG-04 already mandates `docs/hp41-stat1-divergences.md` document it
>     as an emulator extension — NOT part of the "feature-complete per
>     OM 00041-90030" claim
>   - LCG formula `r_{n+1} = FRC(9821·r_n + 0.211327)` is community-confirmed
>     across three independent sources (NPS p. 21, HP-65 User's Library via
>     Don Malm, HP-41C Standard Applications p. 24)
>   - Persistence-surviving `rand_seed` is user-valuable for reproducible
>     simulations

**Why rejected:** adding `#[serde(skip)]` defeats the entire purpose of
STAT-RNG-03 ("reproducible simulations"). A user who runs `SEED 0.5` followed by
`STO 00`, saves, reopens, and calls `RAND` would observe an output computed from
seed `0` rather than from `0.5` — silent drift with no error. The Pitfall 20
trap exists precisely to catch this slip in code review.

### Option C: Separate RNG-state file at `~/.hp41/rand_state.json`

A third option was considered: keep `CalcState`'s serde shape uniform (every
field `#[serde(default, skip)]`) and persist the seed via a sibling file managed
by the persistence layer.

**Why rejected:** adds a second persistence-layer file managed alongside
`~/.hp41/autosave.json`; doubles the file I/O surface; loses the D-33.7 lock
that `CalcState::migrate_after_load()` is the **single** source of truth for
post-load state mutations. CLI and GUI would each need to thread the second
file through their persistence functions, multiplying the divergence surface
between frontends. The save-file backward-compat invariant (`CLAUDE.md §"Save-file
backward compat"`) was deliberately written around a single-file model.

### Option D: `Op` variant carrying the seed (e.g. `Op::RandSeeded(HpNum)`)

A fourth option was considered: model the seed as an argument to a new `Op`
variant rather than as `CalcState` field — the user-visible `XEQ "RAND"` would
desugar to `Op::RandSeeded(state.rand_seed)` with the next-seed value computed
inline.

**Why rejected:** breaks ADR-v3.0-001 (Op-strategy A) which locked "one Op
variant per HP-41 function" as the canonical shape. A `RandSeeded` variant would
either double-cover the `Rand` mnemonic (two Op variants for one user-facing
operation, violating the 4-way exhaustive-match invariant's purpose) or
introduce a "seedless" `Rand` Op that delegates to `RandSeeded` (adding a layer
of indirection with no semantic value). The `CalcState`-field approach lets
`Op::Rand` remain a leaf operation in the dispatch table.
