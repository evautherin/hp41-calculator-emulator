Header metadata block (mirror v3.0-003 / v3.0-005 shape):

- Title H1: "ADR-v3.1-001: RNG State Placement — rand_seed: HpNum on CalcState with serde-default WITHOUT serde-skip"
- Status: Locked 2026-05-22
- Owner: Plan 33-01 + Plan 33-08
- Requirement refs: STAT-RNG-01, STAT-RNG-02, STAT-RNG-03, STAT-RNG-04, Pitfall 20 (serde-default-vs-skip muscle-memory trap from research/PITFALLS.md)
- Downstream consumer: hp41-core/src/state.rs:201-202 (rand_seed: HpNum field with unique serde shape); hp41-core/src/ops/stat1/rand.rs (op_rand, op_seed); hp41-core/tests/stat1_rand_determinism.rs (round-trip test)
- ADR write-up prose: Phase 35 / STAT-DOC-04 (narrative ADR; lock happened during Phase 33 discuss-phase 2026-05-22 / D-33.4)

Sections:

1. Context — Frame the problem: v3.1 adds RAND/SEED as a community-convention extension (NPS p. 21-22 + HP-65 User's Library Don Malm + HP-41C Standard Applications p. 24); reproducible simulations require the seed to survive serde save/load; every other v3.1 CalcState field uses either serde-skip or serde-default (skip for transients, default for new fields needing backward-compat with v3.0 saves). The RNG seed is unique: it must be default (not skip) because the user expects seeded reproducibility across sessions — but it ALSO must not break v1.0–v3.0 save-file backward compat (Pitfall 24).

2. Decision — Lock the unique serde shape: rand_seed: HpNum field on CalcState with serde-default ONLY (NOT additionally serde-skip). The default is HpNum::zero(). The seed is initialized via XEQ SEED ALPHA prompt (STAT-RNG-02), updated on every XEQ RAND call (STAT-RNG-01 LCG formula), and serialized to ~/.hp41/autosave.json on every 30s auto-save cycle. v1.0–v3.0 save files load via the serde-default fallback (rand_seed = 0); the first XEQ RAND from a zero seed returns FRC(0 + 0.211327) = 0.211327 (33-REVIEW.md IN-05 documents this; ADR-v3.1-001 explicitly accepts the IN-05 behavior as expected).

3. Consequences:
   - Positive: reproducible simulations across save/load cycles (STAT-RNG-03); v3.0 backward-compat preserved (loads with rand_seed = 0 default); only ONE new CalcState field added in v3.1 (Pitfall 20 muscle-memory trap mitigated — every other v3.1 CalcState field follows the standard skip pattern; rand_seed is the documented exception).
   - Negative: the IN-05 first-call-from-zero behavior is potentially surprising (a user who never calls SEED but calls RAND repeatedly gets a deterministic sequence starting from 0.211327). Mitigated by D-35-12 (Plan 35-02 divergences entry, if IN-05 routed there) or by ADR-v3.1-001 Footnotes (this ADR; planner picks based on Plan 35-02 outcome).
   - Neutral: the state.rs:201-202 line range is the canonical reference for the serde shape; field-level CI guard is rand_seed_serde_round_trip test in state.rs:721 (Phase 33 Plan 33-01).

4. Alternatives Considered — Three rejected alternatives. Each as a sub-heading with a blockquoted verbatim quote from 33-CONTEXT.md + a "Why rejected" paragraph:
   - Option B: serde-skip on rand_seed (always reset to zero on load) — quote the 33-CONTEXT.md D-33.4 / D-33.7 rejected-option discussion verbatim (planner runs `grep -nE "rand_seed|skip" .planning/phases/33-.../33-CONTEXT.md` to find the exact lines). Why rejected: defeats the purpose of SEED (no reproducibility across sessions).
   - Option C: separate RNG-state file at ~/.hp41/rand_state.json — paraphrase rejection: adds a second persistence-layer file; loses the v3.0 D-33.7 "single source of truth via CalcState::migrate_after_load()" invariant.
   - Option D: Op variant carrying the seed (e.g., Op::RandSeeded(HpNum)) — paraphrase rejection: breaks the v3.0 ADR-001 (Op-strategy A) per-Op-per-function invariant; would force a second Op::Rand / Op::RandSeeded distinction without semantic value.

5. Footnotes / References — Markdown footnotes:
