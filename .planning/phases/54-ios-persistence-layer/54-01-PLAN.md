## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| iOS sandbox ↔ filesystem | The resolver chooses WHERE on-device state is written; a wrong path silently loses state or writes outside the intended container |
| autosave.json ↔ deserializer | A corrupt/crafted file crosses into `load_state()` (serde_json) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-01 | Information Disclosure | `state_path_for_app` mobile branch | mitigate | Resolve via Tauri PathResolver `app_local_data_dir()` (system-derived, no user input); Application Support is inside the app sandbox container — not world-readable |
| T-54-02 | Denial of Service | `app_local_data_dir()` returns Err (#12552) | mitigate | `unwrap_or_else` fallback to `dirs::home_dir()`-based Application Support path + `eprintln!` log; app never panics on the path lookup, starts fresh if load fails |
| T-54-03 | Tampering | malformed autosave.json | accept | Existing pattern: `load_state` returns `Err` → lib.rs setup falls back to `CalcState::new()` (D-03); never panics. No new surface added this plan |
| T-54-04 | Spoofing | path traversal via persisted path field | mitigate | P-iOS-29 audit (Task 3) confirms no `CalcState` field stores a filesystem path; absolute-path persistence across container-UUID change is therefore impossible |
| T-54-05 | Information Disclosure | iCloud backup of Application Support (D-54.1) | accept | D-54.1 explicitly accepts iCloud-backup-by-default for app-managed RPN state; no PII, no secrets in CalcState |
| T-54-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages this phase (RESEARCH Package Legitimacy Audit: `dirs`/`tauri` pre-approved, already present); no install task → no blocking checkpoint required |

No `high`-severity threats remain unmitigated. T-54-02 (the only DoS-class risk) is mitigated by the fallback chain and confirmed on-device in 54-03.
