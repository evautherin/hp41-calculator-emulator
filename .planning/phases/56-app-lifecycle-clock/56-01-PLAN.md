<critical_research_findings>
- The JSON key is `backgroundThrottling` (camelCase, NO `Policy` suffix), at path
  `app.windows[0].backgroundThrottling`. `backgroundThrottlingPolicy` (in CONTEXT/REQUIREMENTS/STATE)
  is the Rust TYPE name, NOT the JSON field. Value: `"throttle"`. Using the wrong name silently
  no-ops (Tauri ignores unknown keys).
- `tauri.ios.conf.json` merges over `tauri.conf.json` via JSON Merge Patch (RFC 7396).
  Arrays are REPLACED wholesale, not deep-merged. Because `app.windows` is an array, the override
  MUST repeat the COMPLETE base window object (title, width, height, resizable, decorations, visible)
  and ADD `backgroundThrottling`. An override with only `backgroundThrottling` would drop the
  window's title/size/`visible:false`.
- No companion Info.plist key required (`backgroundThrottling` → `WKPreferences.inactiveSchedulingPolicy`,
  a runtime API call) — MEDIUM confidence; the D-56.4 device checkpoint is authoritative.
- Read `needsTick`'s live value inside the empty-deps `visibilitychange` listener via a
  `needsTickRef` synced by a `useEffect([needsTick])`, mirroring `busyRef`/`liveTickRef`.
  Do NOT add `needsTick` to the listener's deps (re-registers every 100ms tick — violates D-56.1).
- The resume tick is a single `invoke('tick_time')` gated on `isIos && needsTickRef.current`,
  fired on the `document.visibilityState === 'visible'` branch. NOT a `get_state` resync (D-11).
</critical_research_findings>
