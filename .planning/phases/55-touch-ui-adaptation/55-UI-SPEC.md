# Phase 55 — Touch UI Adaptation: Design Contract

> Visual and interaction contract for the iOS touch adaptation layer.
> Generated by gsd-ui-researcher. Verified by gsd-ui-checker.
>
> This is NOT a redesign. The existing HP-41 faithful visual identity,
> theme system (dark/light/classic-beige/high-contrast), and CSS variable
> architecture are preserved in full. The contract describes the
> touch-adaptation layer only: hit-target sizing, safe-area insets, press
> feedback, tap-delay elimination, ALPHA on-screen entry, haptics, audio
> unlock, annunciator/stack legibility, bottom-sheet panels, and
> overscroll suppression.

## Hit-Target Architecture

**Problem (P-iOS-20):** SVG key geometry is `KEY_W=68, KEY_H=44` design units. At iPhone SE scale (×0.957), keys render as ~65×42pt — below Apple HIG 44pt minimum height. The key label area (`SHIFT_LABEL_H=11 + KEY_H=44 + ALPHA_LABEL_H=11 = 66 total allocated height`) includes label space, but the clickable SVG rect is only KEY_H=44.

**Solution: Transparent hit-area overlays (i41CX+/Free42 pattern)**

Each key gets an absolutely positioned transparent `<div>` overlay that:
- Has `min-width: 44pt; min-height: 44pt` (CSS pt = device points via viewport meta)
- Is centered on the key's visual center (uses `position: absolute` anchored to the SVG bounding box)
- Receives the `onTouchStart`/`onClick` events instead of the SVG element directly
- Has `touch-action: manipulation` to eliminate the 300ms tap delay
- Has `-webkit-tap-highlight-color: transparent` to suppress the default tap flash
- Does NOT obscure neighboring keys: overlays use `pointer-events` discipline — if two keys' extended hit areas would overlap, priority goes to the key whose center is closer to the touch point (standard iOS behavior with `pointer-events: auto` since each overlay is non-overlapping in the 44pt constraint)

**Transparent overlay CSS class** (new, named `key-touch-target`):

```css
.key-touch-target {
  position: absolute;
  min-width: 44px;   /* 44pt via viewport meta */
  min-height: 44px;
  touch-action: manipulation;
  -webkit-tap-highlight-color: transparent;
  cursor: pointer;
  /* center alignment: transform applied by layout code */
  transform: translate(-50%, -50%);
  top: 50%;
  left: 50%;
}
```

**Viewport meta (index.html):** Must include `viewport-fit=cover` alongside the standard mobile meta:
```html
<meta name="viewport" content="width=device-width, initial-scale=1.0, viewport-fit=cover">
```

## Safe-Area Insets

| Location | CSS rule | Minimum fallback |
|----------|----------|-----------------|
| Top (notch/Dynamic Island) | `padding-top: env(safe-area-inset-top, 0px)` on `.calculator` wrapper | 0px |
| Bottom (home indicator) | `padding-bottom: env(safe-area-inset-bottom, 0px)` on `.calculator` wrapper | 0px |
| Left/Right | `padding-left: env(safe-area-inset-left, 0px)` / right | 0px (portrait only) |

The `computeScale` function currently measures `offsetWidth`/`offsetHeight` of the content node. After safe-area padding is applied to the wrapper, the content node's available size shrinks by the inset amounts. The `ScaledApp` component's scale recomputation will correctly account for this via the existing `ResizeObserver` pattern — no code change needed in `scale.ts`.

**Overscroll suppression (TOUCH-11 — partially done):**
`index.css` already sets `overscroll-behavior: none` + `position: fixed; inset: 0` on `body`. This is sufficient for the calculator body. The bottom sheets and stack panel must NOT set `overscroll-behavior: auto` — they must use `-webkit-overflow-scrolling: touch` for smooth inner scrolling without outer bounce.

## Tap Feedback Contract (TOUCH-03)

| Mechanism | Implementation |
|-----------|---------------|
| 350ms delay elimination | `touch-action: manipulation` on every `.key-touch-target` (also on `<body>`) |
| Tap-highlight suppression | `-webkit-tap-highlight-color: transparent` on `.key-touch-target` and `body` |
| Visual press feedback | Existing `.key-pressed` + `scale(0.92)` + `transition: transform 80ms ease-out` — triggered on `pointerdown`, cleared on `pointerup`/`pointercancel` |
| Press state trigger event | `pointerdown` (fires immediately, before any tap-delay) — replace the existing `onMouseDown` handler with `onPointerDown` |

**Event handler change:** The existing SVG `onClick` handler must be supplemented with `onPointerDown` for the press visual + haptic trigger, and `onPointerUp`/`onPointerCancel` for press release. The IPC `dispatch_op` call remains in the `onClick` / `onPointerUp` path (fires once per tap).

## Haptics Contract (TOUCH-05, TOUCH-08)

**Plugin:** `tauri-plugin-haptics` v2.3.2 (add to `Cargo.toml` and `package.json` — not yet present).

**Intensity tiers:**

| Tier | Key type | Haptic call | Pattern |
|------|----------|-------------|---------|
| Light | Standard keys (digits, math ops, trig) | `impactFeedback({ style: 'Light' })` | Single light tap |
| Medium | Function keys (STO, RCL, XEQ, ENTER, R/S, GTO) | `impactFeedback({ style: 'Medium' })` | Single medium tap |
| Heavy | SHIFT key (arms the one-shot shift state) | `impactFeedback({ style: 'Heavy' })` | Single heavy tap |
| Error | DATA ERROR / NO ROOM display event | `notificationFeedback({ type: 'Error' })` | iOS error pattern (double-tap) |

**Tier classification logic:**
- Tier detection fires on `pointerdown`, before the IPC call.
- Key tier is determined by `keyDef.variant` and `keyDef.id`:
  - `variant === 'shift'` → Heavy
  - `variant === 'enter'` OR `id` in `['sto_prompt', 'rcl_prompt', 'xeq_prompt', 'gto_prompt', 'r_s', 'rtn', 'sst', 'bst']` → Medium
  - All other ids → Light
  - `variant === 'top'` (ON/USER/PRGM/ALPHA) → Light

**Error haptic trigger:**
- After each IPC response, check `calcState.display_str` or `calcState.event_buffer` for `'DATA ERROR'` or `'NO ROOM'`.
- If detected, call `notificationFeedback({ type: 'Error' })` once (guard with a ref to prevent double-fire on the same error display).

**iOS guard:** All haptic calls must be wrapped in a platform check — `tauri-plugin-haptics` is a no-op on desktop platforms; Tauri handles this automatically. No conditional needed in JS.

## Audio Contract (TOUCH-06)

**Problem (P-iOS-05):** WKWebView starts with `AudioContext` in `'suspended'` state. TONE/BEEP are silent until the context is resumed inside a user-gesture handler.

**Solution:**

```typescript
// audioResumeRef: one-shot guard — runs once on the first key pointerdown
const audioResumedRef = useRef(false);

async function ensureAudioResumed(audioCtx: AudioContext): Promise<void> {
  if (audioResumedRef.current) return;
  if (audioCtx.state === 'suspended') {
    await audioCtx.resume();
  }
  audioResumedRef.current = true;
}
```

Call `ensureAudioResumed(audioCtx)` at the top of the `pointerdown` handler, before the IPC call. This fires inside a user-gesture handler so iOS allows the resume.

**Silent-switch behavior:** When the iOS hardware silent switch is engaged, `AudioContext` audio is muted. This matches original HP-41 hardware behavior (calculator silent when muted). Document in Phase 57 TestFlight release notes: "Audio muted when silent switch is on — matches original HP-41C hardware."

## ALPHA Touch Entry Contract (TOUCH-04)

**Design decision:** Use `<input type="text">` approach (option A from STATE.md) rather than a custom on-screen character grid. Rationale: native iOS keyboard provides familiar UX, handles special characters (space, backspace), and requires less code. The grid-based approach is retained as a v4.2 enhancement if user research demands it.

**Component:** `AlphaTouchInput` — a new React component rendered conditionally when `calcState.annunciators.alpha === true` AND the device is iOS (detected via `navigator.platform` or `window.__TAURI_INTERNALS__` iOS flag).

**Visual contract:**

```
┌─────────────────────────────────────────────────────┐
│ ALPHA REGISTER                                [Done] │  ← 11px/700/uppercase header, --panel-header-bg
│ ┌─────────────────────────────────────────────────┐ │
│ │  HP41 CURSOR_                                   │ │  ← 16px, --display-bg, --display-text, monospace
│ └─────────────────────────────────────────────────┘ │
│ [A] [B] [C] ... alpha chars from current display    │  ← optional char preview strip (display-only)
└─────────────────────────────────────────────────────┘
```

**Layout behavior:**
- The `AlphaTouchInput` component renders as a fixed-position bar at the bottom of the calculator layout, ABOVE the iOS software keyboard.
- Uses `window.visualViewport.addEventListener('resize', ...)` to track the keyboard inset and reposition the bar so it stays visible.
- The bar height is 64px (sm×8) — enough for a single input row + header label.

**Input flow:**
- Each character typed in the `<input>` field dispatches `alpha_<CHAR>` via `invoke('dispatch_op', { keyId: 'alpha_' + ch })` for each character in the `input` event diff.
- Backspace dispatches `clx` (CL X/A in ALPHA mode per existing behavior).
- "Done" button or keyboard return dispatches `alpha_toggle` to exit ALPHA mode, then dismisses the input.
- The `<input>` is controlled (value always mirrors the alpha register string from `calcState.display_str`).
- `inputmode="text"` + `autocomplete="off"` + `autocorrect="off"` + `spellcheck={false}` — no autocorrect interference.
- `autoFocus={true}` when ALPHA mode becomes active — brings up the iOS keyboard automatically.

**Positioning CSS:**

```css
.alpha-touch-input-bar {
  position: fixed;
  left: env(safe-area-inset-left, 0px);
  right: env(safe-area-inset-right, 0px);
  background: var(--panel-header-bg);
  border-top: 1px solid var(--panel-border);
  padding: 4px 12px 8px 12px;  /* 4px=xs, 12px=sm-plus, 8px=sm */
  z-index: 80;  /* above all overlays (z-index 60-70 used by help/wizard/settings) */
  /* bottom is set dynamically via visualViewport resize listener */
}

.alpha-touch-input-field {
  width: 100%;
  background: var(--display-bg);
  color: var(--display-text);
  font-family: 'Courier New', Courier, monospace;
  font-size: 16px;  /* prevents iOS auto-zoom on focus (must be >= 16px) */
  padding: 8px 12px;  /* 8px=sm, 12px=sm-plus */
  border: 1px solid var(--panel-border);
  border-radius: 4px;
  caret-color: var(--accent);
}

.alpha-touch-input-field:focus {
  outline: none;
  border-color: var(--accent);
}
```

**iOS zoom prevention:** The `<input>` font-size MUST be 16px or larger to prevent iOS from auto-zooming the viewport on input focus. The existing `computeScale` viewport lock would fight this zoom — 16px is non-negotiable.

## Bottom Sheets Contract (TOUCH-09)

Print panel and PRGM-mode program listing are currently rendered as inline panels below the keyboard. On iPhone they consume vertical space that the keypad needs. They become pull-up bottom sheets on iOS.

**Detection:** Platform is iOS (WKWebView) — use `window.__TAURI_INTERNALS__?.platform === 'ios'` or a `is_ios` Tauri command. On desktop, the existing inline panel behavior is preserved unchanged.

**Sheet anatomy:**

```
┌──────────────────────────────────┐
│                                  │  ← drag handle: 4px bar, 32px wide,
│         ─────                   │    centered, 12px top margin, --text-muted
│                                  │
│  PRINT LOG           [Clear]     │  ← 11px/700/uppercase header + action btn
│──────────────────────────────────│
│  line 1                          │
│  line 2                          │  ← scrollable content, -webkit-overflow-scrolling: touch
│  ...                             │
│                                  │
└──────────────────────────────────┘
```

**Two sheets:**
1. **Print Sheet** — triggered by any `print_lines.length > 0` in `CalcStateView`. Sheet header: "PRINT LOG". Has "Clear" button (dispatches `clear_print_buffer` or resets local state).
2. **PRGM Sheet** — visible when `calcState.annunciators.prgm === true`. Sheet header: "PROGRAM". Shows `program_steps[]` with active step highlight (`.step-active`).

**States:**

| State | Sheet position | Peek content |
|-------|---------------|--------------|
| Collapsed (default) | Bottom: only drag handle + 32px peek visible above safe area | Handle bar + truncated header label |
| Expanded | Sheet rises to 60% of viewport height | Full scrollable content |
| Dismissed | Hidden (sheet `display: none` or `translateY(100%)`) | — |

**CSS implementation:**

```css
.bottom-sheet {
  position: fixed;
  left: env(safe-area-inset-left, 0px);
  right: env(safe-area-inset-right, 0px);
  bottom: 0;
  background: var(--panel-bg);
  border-top: 1px solid var(--panel-border);
  border-radius: 12px 12px 0 0;
  z-index: 55;  /* below overlays (60+), above calculator body */
  transform: translateY(calc(100% - 48px));  /* collapsed: shows 48px peek */
  transition: transform 280ms cubic-bezier(0.32, 0.72, 0, 1);
  will-change: transform;
  /* Content height: let the sheet grow to max-height when expanded */
  max-height: 60vh;
  overflow: hidden;
  padding-bottom: env(safe-area-inset-bottom, 0px);
}

.bottom-sheet.expanded {
  transform: translateY(0);
}

.bottom-sheet-handle {
  width: 32px;
  height: 4px;
  border-radius: 2px;
  background: var(--text-muted);
  margin: 12px auto 8px auto;  /* 12px=sm-plus, 8px=sm */
}

.bottom-sheet-content {
  overflow-y: auto;
  -webkit-overflow-scrolling: touch;
  overscroll-behavior-y: contain;  /* inner scroll, no outer bounce */
}
```

**Interaction:** Single tap on drag handle or header toggles expanded/collapsed. No swipe gesture required for this phase (swipe is a v4.2 enhancement).

## Collapsible Stack Panel Contract (TOUCH-10)

The X/Y/Z/T/L stack panel is useful on desktop but competes for vertical space on iPhone.

**Default state on iOS:** Collapsed (shows only X register row + a chevron button).
**Default state on desktop:** Expanded (existing behavior unchanged).

**Toggle control:** A small chevron button (`▲`/`▼`) positioned at the right edge of the stack panel header row. Minimum touch target: 44×44pt (extend with padding).

**Collapsed state:** Only the X register row is visible.
**Expanded state:** All five rows (X/Y/Z/T/L) visible (existing behavior).

**Persistence:** Stack panel state is local React state only — not persisted to `GuiPrefs`. Resets to collapsed on each app launch on iOS.

**Animation:** `max-height` transition from 0 to auto (via explicit max-height value), 200ms ease-out.

**CSS:**

```css
.stack-panel-collapsible {
  overflow: hidden;
  max-height: 200px;
  transition: max-height 200ms ease-out;
}

.stack-panel-collapsible.collapsed {
  max-height: 0;
}

.stack-panel-toggle-btn {
  background: transparent;
  border: none;
  cursor: pointer;
  color: var(--text-muted);
  min-width: 44px;
  min-height: 44px;
  display: flex;
  align-items: center;
  justify-content: center;
  font-size: 11px;
  touch-action: manipulation;
  -webkit-tap-highlight-color: transparent;
}
```

## Annunciator Legibility (TOUCH-07)

Current annunciator size: 11px, opacity 0.35 (inactive). On iPhone SE at scale 0.957, rendered at ~10.5px — legible but tight.

**Contract:** No size change. The scaled display at ≈10.5px with 0.35 opacity inactive / 1.0 opacity active is sufficient for the annunciator indicators given their all-caps + letter-spacing: 0.05em rendering. If legibility testing on device reveals issues, bump to 13px in a follow-up task (not blocking Phase 55).

**ALPHA annunciator:** Already uses `--alpha-label-active` (blue). When ALPHA mode is active, the `AlphaTouchInput` bar appearing confirms the state visually — the annunciator is secondary confirmation.

| Element | Copy |
|---------|------|
| ALPHA input bar header | "ALPHA REGISTER" |
| ALPHA input "Done" button | "Done" |
| Print sheet header | "PRINT LOG" |
| Print sheet clear button | "Clear" |
| PRGM sheet header | "PROGRAM" |
| Stack panel collapse button | chevron glyph `▲` (expanded) / `▼` (collapsed) |

**iOS-idiomatic single-word CTAs (intentional):**

- "Clear" (print sheet) is intentional iOS idiom for a destructive-but-reversible action on an ephemeral buffer. The print buffer is session-only (not persisted); content is easily regenerated by re-running the program. No confirmation dialog is required.

**Empty states:**
- Print sheet with no lines: "No print output yet." (13px, `--text-secondary`, centered)
- PRGM sheet with no steps: "Program memory empty." (13px, `--text-secondary`, centered)

**Error states:**
- DATA ERROR display: shown in the existing main display via `CalcStateView.display_str` — no additional copy. Error haptic fires automatically.
- NO ROOM display: same as above.
