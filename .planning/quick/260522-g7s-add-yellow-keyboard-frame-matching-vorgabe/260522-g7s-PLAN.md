# Quick Task 260522-g7s — GUI Yellow Keyboard Frame

## Goal

Add a thin gold/yellow trim line that runs along the outer perimeter of the
keyboard SVG so the on-screen look matches the user-supplied reference
(`~/Downloads/gui-vorgabe.png`). Purely cosmetic; everything else stays.

## Reference

- Reference image (target):    `~/Downloads/gui-vorgabe.png`
- Current implementation:      `~/Downloads/hp-41cv.png`
- Difference:                  reference has a thin gold/yellow outline
                               running around the entire keyboard panel
                               (between the dark body and the outer edge);
                               current implementation has no such outline.

## Design

The keyboard is one SVG rendered by `hp41-gui/src/Keyboard.tsx`. The body
is drawn as:

```jsx
<rect width={KEYBOARD_W} height={KEYBOARD_H} fill="url(#body-grad)" rx={10} />
<rect width={KEYBOARD_W} height={14} fill="url(#bevel-hi)" rx={10} opacity={0.4} />
```

Add a third rect — drawn AFTER the body and bevel, BEFORE the keys — as a
stroke-only outline inset by `~1.25px` so the 1.5px stroke is fully visible
inside the viewBox (SVG strokes are centered on the path; without the inset
the outer half would be clipped at `x = 0` / `y = 0`).

```jsx
{/* HP-41 gold trim — matches the brass keyboard surround on the physical unit. */}
<rect
  x={1.25}
  y={1.25}
  width={KEYBOARD_W - 2.5}
  height={KEYBOARD_H - 2.5}
  fill="none"
  stroke="#c8b878"
  strokeWidth={1.5}
  rx={8.75}
/>
```

Color rationale: `#c8b878` is a warm pale gold that reads as metallic trim
against the dark body — close to the reference, and in the same family as
the SHIFT key cap (`#d68a1c`) without competing with it.

Stroke is placed BEFORE the `KEY_DEFS.map(...)` loop so keys draw on top
(visually irrelevant in practice — the keys are entirely inside the inset
frame — but preserves the document order invariant of "frame chrome → keys").

## Out-of-scope

- `.calculator` div border in `App.css` (the outer container around display
  + keyboard) — the reference shows only the keyboard region, so we only
  touch the keyboard SVG.
- Any change to the dark body gradient, bevel highlight, key caps, key
  spacing, label colors, or animations.
- Backend, IPC, `key_map.rs`, `prgm_display.rs`, `Op` enum — untouched.

## Risks

- **Snapshot tests:** none of the existing GUI tests are snapshot-based;
  they query by `data-key-id` / role, so adding a non-interactive `<rect>`
  is invisible to them.
- **CLI ↔ GUI parity (D-25.6):** unaffected — this is GUI-only chrome,
  no state, no IPC, no `CalcState` field.
- **Performance:** a single extra rect is negligible.
