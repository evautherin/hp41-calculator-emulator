    Replace FSOLVE and FINTG stubs in solvers.rs with full implementations.

    **FSOLVE** (ADV-MATH-03): Brent/secant root-finding method, closely following the Math Pac I SOLVE pattern in `math1/solve.rs` but using the separate `adv_fsolve_state` field. 

    The dispatch arm (`op_adv_fsolve`) checks `state.is_running` — if false, returns `HpError::InvalidOp` (solver requires program context). If true: read function label from ALPHA or from a register convention per OM, read initial bracket [x1, x2] from Y and X. Initialize `AdvFsolveState` with these values. Set `state.adv_fsolve_state = Some(...)`.

    The run_loop arm (`op_adv_fsolve_run_loop`) is called by execute_op/run_loop on each iteration. It reads f(x) from X (the user program evaluated f at the current x), applies the secant/Brent step to update x, writes the new x to X, and returns to the user program for the next evaluation. When converged (|f(x)| < 1e-10 or |x_new - x_old| < 1e-12): clear `adv_fsolve_state`, push root to X, push to print_buffer. When max iterations (100) exceeded: return `HpError::NoRoot`, push "NO ROOT" to print_buffer.

    **Nesting guard (D-43.7):** FSOLVE only checks `state.adv_fsolve_state.is_some()` — does NOT check `adv_fintg_state`. This allows FINTG to run inside FSOLVE's callback.

    **FINTG** (ADV-MATH-04): Romberg integration, using the separate `adv_fintg_state` field. Read function label, lower bound a (from Y), upper bound b (from X). Initialize `AdvFintegState`. The run_loop arm implements the Romberg tableau: start with trapezoidal rule, then refine with Richardson extrapolation. Each iteration needs the user program to evaluate f(x) at several points — the state machine tracks which evaluation is pending.

    **Nesting guard (D-43.7):** FINTG only checks `state.adv_fintg_state.is_some()` — does NOT check `adv_fsolve_state`. This allows FSOLVE to run inside FINTG's callback.

    **Cancel flag:** Both solvers check `state.cancel_requested.load(Ordering::Relaxed)` every N iterations (match the Math Pac I pattern of checking every 64 evaluations).

    Also update ops/program.rs execute_op to route Op::AdvFsolve and Op::AdvFintg through the run_loop mechanism (this may already be stubbed from Plan 43-01; ensure the run_loop arms call `op_adv_fsolve_run_loop` and `op_adv_fintg_run_loop`).

    **FDIFEQ** (ADV-MATH-05): RK4 ODE solver following the Math Pac I DIFEQ pattern with separate `adv_fdifeq_state`. Supports 1st and 2nd order. Modal prompt for ORDER=? (1 or 2), then function name. Run_loop arms implement classical RK4 steps calling the user program for f(x,y) evaluations.

    **FROOT** (ADV-MATH-06): Laguerre's method for polynomial roots of arbitrary degree. D-43.8 (Claude's discretion): degree from X register, coefficients in R01..R(degree+1) highest-degree first. Algorithm from Numerical Recipes Section 9.5:

    For each root: start with initial guess x0 = 0. Iterate Laguerre step: evaluate P(x), P'(x), P''(x) via Horner's method. Compute G = P'/P, H = G^2 - P''/P. Denominator = G +/- sqrt((n-1)*(n*H - G^2)). Choose sign to maximize |denominator|. Step: a = n / denominator. Update x -= a. Converge when |a| < tolerance. After finding root, deflate polynomial by dividing out (x - root). Repeat for next root.

    Store found roots in `FrootState.roots_found` as (re, im) pairs. Complex roots come in conjugate pairs. Push roots to registers or print_buffer for user access via RTS.

    All Laguerre arithmetic uses f64 (not HpNum) for numerical stability, converting back to HpNum at the end.

    **PLY** (ADV-MATH-07): Polynomial evaluation using Horner's method. Read degree from registers, evaluate P(x) where x is in stack X. Coefficients in R01..R(degree+1). Push result to X. LiftEffect::Enable.

    **RTS** (ADV-MATH-08): Root output — read roots from the last FROOT computation stored in `adv_froot_state` (or a result cache). Push roots to X one at a time (each call advances to next root). Push real part to X, imaginary part to Y if complex.
