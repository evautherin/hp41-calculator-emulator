    **matrix_workflow.rs** — replace stubs:

    **MATRX** (ADV-MATH-01): Full matrix workflow modal. Opens with AdvantageStep::MatrixNamePrompt — "MATRIX NAME?". User enters name in ALPHA, presses R/S. submit_step reads ALPHA, checks if matrix exists. If not, advances to DimRowPrompt — "ROWS?". Then DimColPrompt — "COLS?". After dimensions entered, calls op_adv_matdim internally. Then advances to MatrxOperationChoice — "DET/INV/SYS?". User enters 1/2/3, submit_step dispatches to op_adv_mdet/op_adv_minv/op_adv_msys. Clears modal on completion.

    **MTR** (ADV-MATH-02): Simplified matrix entry/solve. Opens with MtrNamePrompt — "MTR NAME?". After name entry, if matrix exists, presents operation choice directly (skip dimension prompt). If not, prompts for dimensions, creates matrix, then element-by-element entry (using MeditElementPrompt loop), then operation choice.

    **MEDIT** (ADV-MTX-49): Real matrix editor. Opens modal with element prompts. For each element (i,j), prompts "R{i+1}C{j+1}=?" and writes the entered value via op_adv_ms after advancing I/J. Iterates row-by-row. Clears modal after last element or on Esc cancel.

    **CMEDIT** (ADV-MTX-50): Complex matrix editor. Same as MEDIT but prompts for real and imaginary parts per element: "R{i}C{j} RE=?" then "R{i}C{j} IM=?". Writes to complex matrix interleaved data.

    **modal.rs** — wire submit_step:

    Replace the stub `submit_step` implementation with real dispatch for all AdvantageStep variants. Pattern: 
    1. Match on step variant
    2. Read user input from state.stack.x (numeric) or state.alpha_reg (label)
    3. Validate input
    4. Advance modal_program to next step OR clear modal if workflow complete
    5. Set modal_prompt for next step
    6. Call underlying op functions where needed (e.g., op_adv_matdim, op_adv_mdet)

    Clear `state.modal_program = None; state.modal_prompt = None;` BEFORE dispatching to the underlying operation (following the stat1/modal.rs pattern at lines 153-160 — clear modal before dispatch so the op sees clean context).

    For TVM-related AdvantageStep variants (TvmN, TvmI, TvmPv, TvmPmt, TvmFv): wire them to call the corresponding tvm.rs op functions. These are implemented in Plan 43-09 — for now, submit_step for TVM steps can delegate to the tvm.rs functions (which are still stubs in this wave but will be replaced).

    For VeComponentPrompt: store each component to the correct vector register, advance to next prompt (0->1->2->done).

    For FdifeqOrderPrompt/FdifeqFunctionNamePrompt: set up the FDIFEQ state machine per solver conventions.
