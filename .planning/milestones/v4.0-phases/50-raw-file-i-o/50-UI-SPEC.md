## Component Inventory

New components introduced by Phase 50 (to be built using established patterns):

### 1. Multi-Program Picker Overlay (`RawPickerOverlay`)

- **Pattern basis:** `.help-overlay` (absolute position, `z-index: 60`, `var(--overlay-bg)` background, flex column). Reuses `.wizard-overlay` positioning and `.help-overlay-header` header bar.
- **Focal point:** The "SELECT PROGRAMS" heading in the header bar is the primary visual anchor — rendered at 14px/700/ALL CAPS in `var(--accent)` against the secondary-color header bar, drawing the eye immediately on overlay open.
- **Trigger:** WPRGM or RDPRGM card reader op fires with empty ALPHA register; Tauri backend returns a list of decoded programs.
- **Layout:**
  - Header bar: "SELECT PROGRAMS" heading (14px/700 uppercase, accent) + count chip + close button (`×`, 22px, accent on hover).
  - List body: scrollable, `max-height` fills remaining overlay space minus header + footer.
  - Each row: `display: grid; grid-template-columns: 24px 1fr 80px;` — checkbox | program name | size badge.
  - Footer: "Import Selected (N)" primary button + "Cancel Import" secondary button.
- **Program name format:** `QUAD (47 bytes)` or `Program 2 (23 bytes)` — monospace font, 12px.
- **Multi-select:** Standard HTML `<input type="checkbox">` per row. "Import Selected" button shows count in label.
- **Empty list:** Shows "No programs found in this file." in `var(--text-secondary)` at 14px.
- **z-index:** 60 (same level as `.help-overlay` and `.wizard-overlay` — mutually exclusive with both).
- **CSS classes:** `.raw-picker-overlay`, `.raw-picker-header`, `.raw-picker-list`, `.raw-picker-row`, `.raw-picker-name`, `.raw-picker-size`, `.raw-picker-footer`.

### 2. Toast (reused — no new component)

- **Reuse:** Existing `.toast` class in `App.css` + `showToast()` function in `App.tsx`.
- **No changes needed.** Phase 50 calls `showToast("Imported QUAD (47 steps)")` on success.

## Interaction Contracts

### Import flow (GUI — single-program .raw)

1. User presses RDPRGM key with empty ALPHA register.
2. Native OS file dialog opens (`.raw` filter + "All Files" fallback via `tauri-plugin-dialog`).
3. On file selection: Tauri backend decodes file.
4. If single program: inserts via `insert_program_ops`, returns updated `CalcStateView`.
5. Toast shown: `"Imported {LABEL} ({N} steps)"`. Duration: 2 s (existing animation).
6. Auto-save triggered after successful import.

### Import flow (GUI — multi-program .raw archive)

1-3. Same as single-program steps 1–3.
4. If multiple programs detected: `RawPickerOverlay` renders with full program list.
5. User checks desired programs and clicks "Import Selected (N)".
6. Programs inserted sequentially via `insert_program_ops`.
7. Toast: `"Imported {N} programs"`.
8. Auto-save triggered.
9. On "Cancel Import": overlay dismisses, calculator state unchanged.

### Import error flow (GUI)

- File decode fails: existing error-row (`var(--error-bg)` / `var(--error-text)`) shows "Import failed: {reason}". No toast for errors — error row is persistent until next operation.
- Empty file or zero programs decoded: toast `"No programs found in file"` (2 s, uses toast styles).

### Export flow (GUI)

1. User presses WPRGM key with empty ALPHA register.
2. Native OS save dialog opens (`.raw` default extension via `tauri-plugin-dialog`).
3. Tauri backend encodes current program, writes to selected path.
4. Toast: `"Saved {LABEL}.raw"` on success.
5. On dialog cancel: no state change, no feedback.

### Data card import/export flow (GUI)

- Same empty-ALPHA trigger pattern as programs.
- Import (RDTA with empty ALPHA): `.card.json` file filter, toast `"Loaded data card"` on success.
- Export (WDTA with empty ALPHA): `.card.json` default extension, toast `"Saved data card"` on success.

### CLI flags

- `--import-raw FILE` / `--import-raw -` (stdin): load program then start interactive TUI.
- `--export-raw FILE` / `--export-raw -` (stdout): export current program, exit 0.
- `--import-data FILE` / `--import-data -`: load `.card.json` data card.
- `--export-data FILE` / `--export-data -`: export `.card.json` data card.
- `--batch` / `--no-tui`: suppress interactive TUI, exit 0 after operation.
- CLI errors print to stderr; exit 1 on failure.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA — import single | "Import Program" |
| Primary CTA — import multi-select | "Import Selected (N)" where N = checkbox count |
| Primary CTA — export | "Save Program" |
| Picker overlay heading | "SELECT PROGRAMS" |
| Picker secondary dismiss | "Cancel Import" |
| Toast — import success (single) | "Imported {LABEL} ({N} steps)" |
| Toast — import success (multi) | "Imported {N} programs" |
| Toast — export success | "Saved {LABEL}.raw" |
| Toast — data card import | "Loaded data card" |
| Toast — data card export | "Saved data card" |
| Toast — no programs found | "No programs found in file" |
| Error row — import failure | "Import failed: {reason}" |
| Picker empty state heading | "No programs found in this file." |
| Picker empty state body | (no body copy — heading is self-contained) |
| CLI — import success stdout | "Imported {LABEL} ({N} steps)" |
| CLI — export success stdout | "Saved {N} bytes to {path}" |
| CLI — stdin piping notation | `--import-raw -` (Unix dash convention) |

Rules:
- Toast messages use sentence case, no trailing period.
- Error messages use sentence case with colon separator: "Import failed: {reason}".
- Picker heading ALL CAPS (matches existing `.settings-section-heading` uppercase pattern).
- Program names in all caps (HP-41 label convention): "QUAD", "STAT", "TVM".
- Fallback program name when no LBL found: "Program N" (capital P, ordinal number).
- Secondary dismiss labels use verb + noun form to disambiguate the action scope ("Cancel Import", not bare "Cancel").

## Accessibility

- Picker overlay must have `role="dialog"` and `aria-label="Select Programs"` (matches `SettingsPanel` pattern).
- Picker close button (`×`) must have `aria-label="Close picker"`.
- Checkboxes must have visible labels via adjacent `<label>` element or `aria-label`.
- "Import Selected" button disabled state when zero checkboxes checked (`disabled` attribute + `opacity: 0.5`).
- Focus management: on picker open, focus the first checkbox. On close, return focus to the triggering element.
- Keyboard: `Escape` closes picker without importing (same as existing overlay dismiss pattern).

## States and Feedback

| State | Indicator |
|-------|-----------|
| File dialog open | Native OS dialog — no in-app feedback needed |
| Picker open | `RawPickerOverlay` rendered at z-index 60 |
| Zero programs selected | "Import Selected (0)" button disabled, opacity 0.5 |
| Import in progress (async) | No spinner needed — Tauri dialog is synchronous from user perspective |
| Import success | Toast (2 s auto-dismiss) |
| Export success | Toast (2 s auto-dismiss) |
| Import error | Error row (persistent, `var(--error-bg)` / `var(--error-text)`) |
| Dialog cancelled | No visual feedback — silent no-op |
