<objective>
Wire tauri-plugin-dialog into the GUI backend and implement all 5 Tauri commands for file dialog import/export of .raw programs and .card.json data cards.

Purpose: RAW-01/RAW-02/RAW-04 require users to import/export via native OS file dialogs. The .raw codec is ready in hp41-core (Plan 01 extends it with multi-program support); this plan adds the Tauri command layer that opens dialogs, reads/writes files, and returns CalcStateView to the frontend. The multi-program path returns structured metadata (program labels + indices) so the frontend can render a picker (Plan 03).

Output: 5 new Tauri commands registered in lib.rs with matching permission TOMLs and default.json entries. tauri-plugin-dialog added as a dependency and registered as a plugin.
</objective>

  <action>
    Add 5 new public Tauri command functions to hp41-gui/src-tauri/src/commands.rs. All follow the anti-deadlock pattern from RESEARCH Pitfall 1: open dialog FIRST (no AppState lock held), do file I/O SECOND (no lock), acquire lock ONLY for state mutation.

    New imports needed at top of commands.rs:
    - use tauri::AppHandle;
    - use tauri_plugin_dialog::DialogExt;
    - use hp41_core::cardreader::raw::{decode_all_programs, picker_label};
    - (encode_program, decode_data, encode_data, insert_program_ops, capture_data_card, load_data_card already available through existing crate-level imports or can be added)

    Each command is annotated with #[tauri::command].

    **1. import_raw_dialog(app: AppHandle, state: State<AppState>) -> Result<serde_json::Value, GuiError>**
    - Phase 1 (no lock): Open file dialog via app.dialog().file().set_title("Import HP-41 Program").add_filter("HP-41 Program", &["raw"]).add_filter("All Files", &["*"]).blocking_pick_file(). If user cancels (None), lock state and return handle_get_state wrapped in serde_json::json!({"view": view}).
    - Phase 2 (no lock): file_path.into_path() to get PathBuf (RESEARCH Pitfall 6). std::fs::read the file bytes.
    - Phase 3: Call decode_all_programs(&bytes). If result has exactly 1 program: lock state, call insert_program_ops with the ops, build the program name from picker_label(0, &ops, byte_len), call handle_get_state, return json!({"view": view, "message": format!("Imported {} ({} steps)", label, ops_count)}) where ops_count is the program ops length.
    - If result has 0 programs: return json!({"view": current_view, "message": "No programs found in file"}).
    - If result has 2+ programs: do NOT import anything yet. Build a programs array with picker_label for each decoded program and return json!({"multi": programs_list}) where programs_list is a Vec of objects {label: String, index: usize, byte_len: usize}. The frontend uses this to show the picker. Store the decoded programs in a temporary Mutex-wrapped cache keyed by a u64 session_id (or simply re-decode on import_selected_programs -- simpler, re-reading the file is fast).

    Actually, the simpler approach for multi-program: return the file path alongside the metadata. The frontend calls import_selected_programs with the path and selected indices, which re-reads and re-decodes.

    Return type can be a custom ImportRawResult enum serialized as JSON with #[derive(Serialize)]:
    ```
    struct ImportResult { view: CalcStateView, message: Option<String> }
    struct MultiProgramInfo { label: String, index: usize, byte_len: usize }
    enum ImportRawResponse { Single(ImportResult), Multi { programs: Vec<MultiProgramInfo>, file_path: String } }
    ```

    **2. import_selected_programs(file_path: String, indices: Vec<usize>, state: State<AppState>) -> Result<CalcStateView, GuiError>**
    - Re-read the file at file_path, decode_all_programs, filter by indices, insert each selected program sequentially via insert_program_ops. Return CalcStateView. The frontend shows toast "Imported N programs".

    **3. export_raw_dialog(app: AppHandle, state: State<AppState>) -> Result<serde_json::Value, GuiError>**
    - Phase 1 (lock briefly): Snapshot program via encode_program(&calc.program). Drop lock.
    - Phase 2 (no lock): Open save dialog via app.dialog().file().set_title("Export HP-41 Program").set_file_name("program.raw").add_filter("HP-41 Program", &["raw"]).add_filter("All Files", &["*"]).blocking_save_file(). If cancelled, return json!({"cancelled": true}).
    - Phase 3 (no lock): save_path.into_path(), std::fs::write. Return json!({"message": format!("Saved {}", filename)}) where filename is the file stem from the path.

    **4. import_data_dialog(app: AppHandle, state: State<AppState>) -> Result<serde_json::Value, GuiError>**
    - Same pattern as import_raw_dialog but for .card.json files. Filter: "HP-41 Data Card" with extension ["card.json"]. Use decode_data, load_data_card. Return json with view and message "Loaded data card". Per D-50.7.

    **5. export_data_dialog(app: AppHandle, state: State<AppState>) -> Result<serde_json::Value, GuiError>**
    - Same pattern as export_raw_dialog but for .card.json. Snapshot via capture_data_card + encode_data. Filter: "HP-41 Data Card" with extension ["card.json"]. set_file_name("data.card.json"). Per D-50.7.

    Error construction: GuiError { message: format!("...") } for ad-hoc errors, GuiError::from(hperr) for HpError conversion.

    Set default directory for all dialogs to cards_dir() (the ~/.hp41/cards/ path), via .set_directory() if available on FileDialogBuilder.

    All import commands that modify state should include the persistence::trigger_save() pattern if it exists, or note that the auto-save thread handles it every 30s.
