## Spacing Scale

Declared values (multiples of 4):

| Token | Value | Usage in this phase                                |
|-------|-------|----------------------------------------------------|
| xs    | 4px   | Annunciator gap, print/prgm panel header padding   |
| sm    | 8px   | Inter-icon gap in title bar, popover item padding  |
| md    | 16px  | Default element spacing, calculator margin         |
| lg    | 24px  | Popover internal section padding                   |
| xl    | 32px  | (reserved — not used in Phase 48)                  |
| 2xl   | 48px  | (reserved — not used in Phase 48)                  |
| 3xl   | 64px  | (reserved — not used in Phase 48)                  |

Exceptions:
- **Touch/click target for gear icon and `?` icon:** minimum 28×28px clickable area despite the icon being rendered at ~16px (accessibility floor for desktop pointer targets).
- **Key face height in SVG:** 44px (KEY_H constant) — preserved from existing Keyboard.tsx, not a spacing token.

Source: existing App.css padding/gap patterns (4px, 8px, 16px observed); defaults for unobserved tokens.

## Typography

| Role          | Size  | Weight        | Line Height | Font                                        |
|---------------|-------|---------------|-------------|---------------------------------------------|
| Body (UI)     | 14px  | 400 (regular) | 1.5         | `system-ui, sans-serif`                     |
| Label (small) | 11px  | 400 (regular) | 1.4         | `system-ui, sans-serif` or monospace panel  |
| Heading       | 13px  | 700 (bold)    | 1.2         | `system-ui, sans-serif` (settings panel section heads) |
| Key label     | 14px  | 700 (bold)    | 1.0         | SVG text — inherited from existing Keyboard.tsx |

Notes:
- `'Courier New', Courier, monospace` is reserved for display, stack, print, and program panel content — it must not bleed into the new settings popover.
- Settings panel text uses `system-ui, sans-serif` at 14px/400.
- Theme names in the radio list render at 14px/400/1.5 — same as body.
- Section heading "Theme" inside the settings panel: 13px/700/1.2.
- The settings panel inherits letter-spacing: normal (no tracking).

Source: existing App.css font-size values (11px annunciators, 13px stack/error, 14px help search, 22px display); existing Keyboard.tsx fontSize 14 (key label) / 13 (ENTER) / 11 (shift + alpha labels).

## Interaction Contract

### Settings Panel (new component: `<SettingsPanel>`)

**Trigger:** Click gear icon `⚙` in the title bar area, placed immediately left of the existing `?` icon.

**Popover behavior (D-48.4):**
- Renders as an absolutely-positioned layer anchored to the calculator container (same `position: relative` anchor as `.toast` and `.help-overlay`).
- `z-index: 70` — above help overlay (`z-index: 60`) and toast (`z-index: 50`).
- Dismisses on click-outside only — no explicit close button (D-48.4, mirrors `?` overlay pattern).
- Does NOT dismiss on Escape (Escape is consumed by help overlay / modal / shift — settings panel has lower priority and a click-outside-only policy).
- Instant open/close — no CSS transition animation (D-48.12, matches utilitarian aesthetic).

**Theme selector (within settings panel, D-48.1/D-48.2):**
- Section heading: "Theme" at 13px/700, `--accent` color.
- Four `<label>` + `<input type="radio">` rows, one per theme.
- Theme names (verbatim): `Dark`, `Light`, `Classic Beige`, `High Contrast`.
- Radio button is the native `<input type="radio">` — no custom styling.
- Clicking a radio button applies the theme instantly (D-48.12) — no "Apply" button needed.
- The calculator itself is the live preview (D-48.2).

**Theme application mechanism:**
- Set `document.body.setAttribute('data-theme', themeName)` where `themeName` ∈ `['dark', 'light', 'classic-beige', 'high-contrast']`.
- `themes.css` contains four `[data-theme="dark"] { ... }` blocks assigning all ~30 CSS variables.
- `App.css` retains all structural/layout rules; hardcoded hex colors are replaced with `var(--token)` references.

**SVG gradient stop handling (D-48.10, P55):**
- `<defs>` gradient stops cannot use CSS `var()` — pass theme config as React props to `<Keyboard>`.
- Keyboard receives a `themeConfig` prop (or equivalent) containing the 9 gradient stop hex values for: body grad, key face (3 stops), enter (3 stops), shift idle (3 stops), shift active (3 stops), bevel highlight.
- These props are derived from the active theme identifier in `App.tsx` state.

**Animation safety (D-48.3, P51):**
- Every `[data-theme]` block in `themes.css` must NOT override `transform-box` or `transform-origin` on `.key`.
- The `.key { transform-box: fill-box; transform-origin: center; }` rule in `App.css` must NOT be moved into a theme block.

**Persistence (D-48.13):**
- On every radio-button change: invoke `set_pref` Tauri command with `{ key: "theme", value: themeName }`.
- On app start: invoke `get_prefs`, read `theme` field, apply to `<body>` before first render (no flash of unstyled content).
- `prefs.json` lives at `~/.hp41/prefs.json` (P59 — never in `autosave.json`).
