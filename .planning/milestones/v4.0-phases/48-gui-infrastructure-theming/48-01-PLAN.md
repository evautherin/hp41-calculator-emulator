Create the Tauri backend preferences layer: a `prefs.rs` module mirroring `persistence.rs`, two new IPC commands (`get_prefs`, `set_pref`), permission TOMLs, and managed state registration.

Purpose: Establishes the `~/.hp41/prefs.json` persistence infrastructure that all v4.0 user-facing preferences will flow through. This is the foundation for theme persistence (Phase 48) and onboarding flags (Phase 49). Ensures theme preference is completely isolated from CalcState/autosave.json (P59, THEME-05).

Output: Working Tauri backend that can load, validate, and persist user preferences. Frontend plans (48-03) consume these commands via `invoke()`.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-48-01 | Tampering | set_pref key/value | mitigate | validate key against known set ("theme"); validate value against allowlist of 4 theme names; return Err for unknowns |
| T-48-02 | Tampering | prefs.json on disk | mitigate | serde_json::from_reader returns Err on malformed JSON -> unwrap_or_default() returns safe GuiPrefs::default() |
| T-48-03 | Information Disclosure | prefs.json contents | accept | prefs.json contains only theme name string — no PII, no secrets, no sensitive data |
