> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

| Property | Value |
|----------|-------|

## Spacing Scale

Declared values (multiples of 4, consistent with existing `App.css`):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, annunciator row padding, inline padding, shortcut-row vertical padding |
| sm | 8px | Panel content padding, radio row vertical padding, gap between overlay search and close button, shortcut-row gap |
| md | 16px | Settings panel padding, overlay content horizontal padding, section heading margins, wizard nav button horizontal padding |
| lg | 24px | Wizard panel body vertical padding |
| xl | 32px | Wizard panel lateral margins on mobile-equivalent viewport |
| 2xl | 48px | Not used in this phase |
| 3xl | 64px | Not used in this phase |

Exceptions:
- Minimum click target: 28×28px for icon buttons (existing `.settings-gear-btn`, `.help-icon-btn` pattern — preserve exactly)
- Overlay content padding: 12px top/bottom, 16px left/right (existing `.help-overlay-content` pattern — reuse for wizard body)

## Typography

Exactly 4 sizes declared. Weights: regular (400) and bold (700) only.

| Role | Size | Weight | Line Height | Family |
|------|------|--------|-------------|--------|
| Body / function description / examples / notes | 12px | 400 (regular) | 1.4 | monospace |
| Section / category heading (existing App.css pattern) | 13px | 700 (bold) | 1.2 | monospace |
| Label / radio row / settings / wizard body / buttons | 14px | 400 (regular) | 1.4 | system-ui |
| Display text (calc display) | 22px | 400 (regular) | — | monospace |

Notes (sourced from `App.css`):
- 12px at weight 400, line-height 1.4 — used for all body text: help overlay rows, print lines, shortcut key/function columns, expand toggle button glyphs, example text, and notes text. The former 10px and 11px values are consolidated into 12px.
- 13px at weight 700 — existing `.settings-section-heading` and category heading pattern; reused for the "Quick Start" settings section heading and the "KEYBOARD SHORTCUTS" overlay section heading.
- 14px at weight 400 — labels, settings radio rows, wizard body paragraphs, wizard panel headers (headers use weight 700), wizard nav button text, "Show Guide" button text.
- Wizard panel headers: 14px at weight 700, uppercase, `var(--accent)` color — same rule as `.help-overlay-section-heading`.
- Do not introduce new font sizes or weights; re-use only the four declared sizes and two weights (400, 700).

## Color

All colors reference CSS custom properties defined in `themes.css`. The design is theme-agnostic — use variables exclusively, never hard-coded hex.

| Role | CSS Variable | Usage |
|------|-------------|-------|
| Dominant (60%) — surfaces | `var(--overlay-bg)` | Wizard overlay background, `?` overlay background |
| Secondary (30%) — panels | `var(--panel-bg)` / `var(--panel-header-bg)` | Wizard panel chrome, settings section headers, shortcut table rows |
| Accent (10%) | `var(--accent)` | Reserved-for list below |
| Destructive | `var(--error-text)` on `var(--error-bg)` | Not applicable in this phase (no destructive actions) |
| Text primary | `var(--display-text)` | Wizard body text, shortcut table function names, expandable example text |
| Text secondary | `var(--text-secondary)` | Function descriptions, shortcut key labels, wizard body paragraphs |
| Text muted | `var(--text-muted)` | Panel borders, inactive elements |
| Panel border | `var(--panel-border)` | Wizard panel container border, shortcut section dividers |

Accent (`var(--accent)`) reserved for:
1. Wizard panel step indicator ("2 of 5") text
2. Section headings in the `?` overlay (including the new "Keyboard Shortcuts" section heading)
3. Function name (`op_variant`) in expandable example blocks
4. "Show Guide" button label text (not background — accent text on `var(--panel-bg)` background)
5. Focus ring on the wizard's Next/Back buttons and the help-overlay search input (existing `.help-overlay-search:focus` pattern: `outline: 1px solid var(--accent)`)
6. `.wizard-nav-btn-primary` border and text color — the primary navigation button on each wizard panel

### Focal Point Declaration

Wizard primary screen (panel 1 "Welcome to HP-41C"): the dominant focal point is the panel header text rendered at 14px bold uppercase in `var(--accent)`, paired with the primary navigation button (`.wizard-nav-btn-primary`) whose border and label text also use `var(--accent)`. All other text uses `var(--text-secondary)` to create clear visual hierarchy. No competing accent elements appear between the header and the primary button.

Dark theme reference values (for implementation verification only — always use variables):
- `--accent` dark: `#f5a423`
- `--accent` light: `#c07010`
- `--accent` classic-beige: `#c8780a`
- `--accent` high-contrast: `#ffaa00`

## Component Inventory

New components introduced in Phase 49:

### 1. `WizardOverlay.tsx`

Full-cover overlay (same layering as `.help-overlay`, z-index 60) with 5 panels.

**CSS classes to add to `App.css`:**

```
.wizard-overlay            — full-cover overlay, position: absolute, z-index 60, background: var(--overlay-bg)
.wizard-panel              — panel container, flex column, padding: 12px 16px
.wizard-panel-header       — panel title row, font-size: 14px, font-weight: 700, color: var(--accent), text-transform: uppercase, letter-spacing: 0.1em
.wizard-panel-counter      — step indicator "N of 5", font-size: 12px, color: var(--accent), margin-left: auto
.wizard-panel-body         — prose content, font-size: 14px, color: var(--text-secondary), line-height: 1.5, font-family: system-ui
.wizard-panel-nav          — button row, display: flex, gap: 8px, justify-content: space-between, padding: 12px 16px
.wizard-nav-btn            — Back/Next buttons, font-size: 14px, padding: 8px 16px, background: var(--panel-bg), border: 1px solid var(--panel-border), color: var(--text-secondary), border-radius: 4px, cursor: pointer
.wizard-nav-btn:hover      — color: var(--accent)
.wizard-nav-btn-primary    — Next/Start button variant, color: var(--accent), border-color: var(--accent)
.wizard-dismiss-link       — "Skip" text button, font-size: 12px, color: var(--text-muted), background: none, border: none, cursor: pointer, text-decoration: underline
.wizard-stack-diagram      — monospace pre block for the X/Y/Z/T stack diagram, background: var(--display-bg), color: var(--display-text), padding: 8px 12px, border-radius: 4px, font-size: 12px, border: 1px solid var(--display-border)
.wizard-shortcut-table     — two-column table for top-10 shortcuts, width: 100%, border-collapse: collapse
.wizard-shortcut-row       — tr, padding: 4px 0, border-bottom: 1px solid var(--panel-border)
.wizard-shortcut-key       — td, color: var(--accent), font-family: monospace, width: 120px
.wizard-shortcut-fn        — td, color: var(--display-text)
```

**Behavior:**
- Renders when `onboardingOpen === true` in `App.tsx` state
- z-index 60 (same as `.help-overlay`; wizard and help overlay are mutually exclusive — only one open at a time)
- Esc and click-outside do NOT dismiss the wizard on first-run (intentional: user must navigate to panel 5 or click "Skip")
- On re-open from SettingsPanel: Esc and click-outside DO dismiss (matches existing overlay dismiss pattern)
- Panel counter: "1 of 5", "2 of 5", ... "5 of 5"
- "Back" disabled on panel 1 (render as muted, `disabled` attribute)
- Panel 5 shows "Start Using HP-41C" instead of "Next" (accent button)
- "Skip" link visible on all panels during first-run; not shown on re-open

### 2. Keyboard Shortcuts section in `HelpOverlay.tsx`

A new top-level section inserted as first entry in the `SECTIONS` array (id: `'shortcuts'`).

**New CSS classes to add to `App.css`:**

```
.shortcut-table            — two-column table, width: 100%, border-collapse: collapse, font-family: monospace
.shortcut-row              — tr, display: grid, grid-template-columns: 140px 1fr, gap: 8px, padding: 4px, border-radius: 2px
.shortcut-row:hover        — background: rgba(200, 230, 201, 0.08) (matches .help-overlay-row:hover)
.shortcut-key-col          — td, color: var(--accent), font-size: 12px
.shortcut-fn-col           — td, color: var(--display-text), font-size: 12px, font-weight: 700
```

**Behavior:**
- Section heading: "Keyboard Shortcuts" (same `.help-overlay-section-heading` class, uppercase, accent color)
- Section starts collapsed by default (unlike function sections which default to expanded)
- Sourced from `docs/keyboard-shortcuts.json` via Vite static JSON-import in `help_data.ts`
- ~30 entries covering: digit keys, ENTER, +/-/×/÷, CHS, EEX, BSP, CLX, F1–F8, Ctrl+W/R/D/F, Ctrl+S, F5, Tab (SHIFT), Backslash (XEQ), arrow keys (SST/BST)
- NOT searchable: the shortcuts section is excluded from the global search filter (physical key mappings have different semantics from function lookup)

### 3. Expandable entries in `HelpOverlay.tsx`

Entries with `example` or `notes` fields in the JSON gain an expand toggle.

**New CSS classes to add to `App.css`:**

```
.help-entry-expand-btn     — inline toggle "▶" / "▼", font-size: 12px, color: var(--text-muted), background: none, border: none, cursor: pointer, margin-right: 4px
.help-entry-detail         — expanded detail block, display: block, margin: 4px 0 8px 96px (indented to align with description column), background: var(--panel-bg), border-left: 2px solid var(--accent), padding: 8px 12px, border-radius: 0 4px 4px 0
.help-entry-example        — monospace example text, font-size: 12px, color: var(--display-text), line-height: 1.5
.help-entry-notes          — notes text, font-size: 12px, color: var(--text-secondary), font-style: italic, margin-top: 4px
```

**Behavior:**
- Toggle state is local to the entry (independent per entry; no global expand/collapse)
- Collapsed by default
- Toggle indicator: "▶" (collapsed) / "▼" (expanded) prepended to the key column cell
- Entries without `example` / `notes`: no toggle, no visual change from current layout

## Interaction Contracts

### Wizard Navigation

| Trigger | Action |
|---------|--------|
| "Next" button | Advance to next panel (panel 1→5); disabled on panel 5 |
| "Back" button | Return to previous panel; disabled (`opacity: 0.4`) on panel 1 |
| "Start Using HP-41C" (panel 5) | Close wizard, set `onboarding_done: true` via `invoke('set_pref')` |
| "Skip for now" | Close wizard, set `onboarding_done: true` via `invoke('set_pref')` |
| Esc (first-run) | No action — wizard stays open |
| Esc (re-open) | Close wizard (no prefs write — already marked done) |
| Click-outside (first-run) | No action — wizard stays open |
| Click-outside (re-open) | Close wizard |

### Expandable Function Entry

| Trigger | Action |
|---------|--------|
| Click on entry with example/notes | Toggle detail block; icon flips ▶ → ▼ |
| Click again | Collapse detail; icon flips ▼ → ▶ |
| Search query change | Expanded state preserved across query changes |
| Overlay closes | All entries reset to collapsed on next open (matches query reset pattern) |

### Keyboard Shortcut Section (in `?` overlay)

| Trigger | Action |
|---------|--------|
| Click "KEYBOARD SHORTCUTS" heading | Toggle collapse/expand (same as other sections) |
| Default state on open | Collapsed |
| Search input active | Section excluded from search filtering; section visibility unchanged |

### New Physical Keyboard Bindings (App.tsx)

| Key | Op ID | Notes |
|-----|-------|-------|
| Ctrl+W | `wprgm` | Card reader: write program |
| Ctrl+R | `rdprgm` | Card reader: read program |
| Ctrl+D | `wdta` | Card reader: write data |
| Ctrl+F | `rdta` | Card reader: read data |
| F5 | `run_stop` | R/S — run/stop |
| Ctrl+S | `save_state` | Manual save to `~/.hp41/autosave.json` |

Implementation note: `resolveKeyId()` must check `e.ctrlKey` before the existing letter-key path; letter keys without Ctrl continue to route through the existing `e.key` match.

## Accessibility Contract

| Element | Requirement |
|---------|-------------|
| Wizard overlay | `role="dialog"`, `aria-label="HP-41C Quick Start Guide"`, `aria-modal="true"` |
| Wizard step counter | `aria-label="Step N of 5"` on the counter span |
| Back button (disabled, panel 1) | `disabled` attribute + `aria-disabled="true"` |
| Expand toggle buttons | `aria-expanded="true/false"`, `aria-label="Show example for {display_name}"` |
| Keyboard shortcuts section heading | `aria-expanded="true/false"` (matches existing section heading pattern) |
| Shortcuts table | `role="table"`, header row with `role="columnheader"` for "Key" and "Function" |
| Skip link | Must be focusable and keyboard-activatable (not `div` — use `<button>`) |
| Color alone | Never used to convey state — always paired with text (▶/▼ icons, "disabled" visual treatment) |
| High-contrast compliance | All new elements use CSS variables; high-contrast theme guarantees 21:1 on `--display-text` / 9.7:1 on `--accent` over `--calc-bg` (#000000) |
