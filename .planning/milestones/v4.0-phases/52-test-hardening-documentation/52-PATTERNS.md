## Pattern Assignments

### `docs/hp41-xmem-functions.json` (data-JSON, transform)

**Analog:** `docs/hp41-advantage-functions.json`

**Entry schema** (lines 1–12 of analog):
```json
{
    "op_variant": "EmDir",
    "display_name": "EMDIR",
    "category": "Extended Memory",
    "status": "implemented",
    "phase": "52",
    "key_path": "XEQ \"EMDIR\"",
    "description": "Catalog all X-MEM files; names + register counts printed to PRINT buffer",
    "example": "XEQ \"EMDIR\" -> prints file list e.g. PROG1 P 20 / DATA1 D 100",
    "notes": "Output goes to print_buffer; drain via PRA/PRX. Empty X-MEM prints nothing."
}
```

**Critical constraints:**
- NO `xrom` field — X-MEM ops are OS built-ins, not XROM. Omitting this field makes `xrom` deserialize as `None` via `#[serde(default)]` on `HelpEntry.xrom`. Adding any `xrom` key would break `test_pool_partition_is_exhaustive` (which only recognizes module_id None, 7, 2, 26, 22, 24).
- `key_path` must be `"XEQ \"EMDIR\""` etc. (XEQ-by-name only; D-52.4). With a non-null `key_path`, entries pass the CLI right-panel filter (`entry.xrom.is_none()` keeps them in) AND the GUI `helpOverlayRows()` filter (`key_path !== null`).
- `category` must be `"Extended Memory"` for all 8 entries — this drives the dedicated overlay section (D-52.1).
- `example` and `notes` fields: present in JSON, silently ignored by Rust serde (no `deny_unknown_fields`). Already supported in GUI `HelpEntry` interface (lines 82–84 of `help_data.ts`). If planner opts to surface them in the matrix doc, `HelpEntry` in `help_data.rs` and `Entry` in `docs-matrix/src/main.rs` need `#[serde(default)] pub example: Option<String>` etc.

**8 entries to create** (op_variant / display_name pairs):
- `EmDir` / `EMDIR`
- `EmRoom` / `EMROOM`
- `SaveP` / `SAVEP`
- `GetP` / `GETP`
- `SaveD` / `SAVED`
- `GetD` / `GETD`
- `EmReg` / `EMREG`
- `SaveRx` / `SAVERX`

**Count function pattern** (lines 326–345 of analog — adapt for xmem):
```rust
fn count_xmem_test_mentions(variant_name: &str, tests_dir: &Path, src_xmem_dir: &Path) -> usize {
    // Scan both external test files (tests/xmem_*.rs) and inline tests in ops.rs.
    // Uses the same line_mentions_variant helper established for other modules.
    let mut count = 0;
    // External test files
    for entry in fs::read_dir(tests_dir).expect("tests dir readable") {
        let path = entry.expect("dir entry").path();
        if path.file_name().and_then(|n| n.to_str())
               .map(|n| n.starts_with("xmem") && n.ends_with(".rs")).unwrap_or(false) {
            let src = fs::read_to_string(&path).unwrap_or_default();
            for line in src.lines() {
                if line_mentions_variant(line, variant_name) { count += 1; }
            }
        }
    }
    // Inline tests in ops.rs
    let ops_path = src_xmem_dir.join("ops.rs");
    if let Ok(src) = fs::read_to_string(&ops_path) {
        for line in src.lines() {
            if line_mentions_variant(line, variant_name) { count += 1; }
        }
    }
    count
}
```

## Key Architectural Notes for Planner

1. **GUI has its own `help_data.ts`** (TypeScript, Vite imports) at `hp41-gui/src/help_data.ts` — NOT a Rust file. It must be extended in parallel with the Rust `help_data.rs`. The GUI `helpEntriesAll()` at line 236–238 follows the same spread-concat pattern; X-MEM is the sixth element.

2. **`builtin_card_op` is already `pub`** — the reverse parity test in `function_matrix_parity.rs` can call `hp41_core::ops::program::builtin_card_op(name)` directly. There is a test alias `__test_builtin_card_op` at line 1451–1454 of `program.rs` for backward compat; new tests should use the real function directly.

3. **Test-count floor gate must come after tests** — EmDir (2 mentions), EmRoom (4), GetD (3), SaveRx (2) are currently below the ≥5 floor. The isolation tests in `xmem_backward_compat.rs` plus supplementary XEQ-by-name integration tests will bring these up. Add the `xrom_op_test_count.rs` extension only after the supplementary tests exist.

4. **No `migrate_after_load()` arm needed** — `xmem_files` and `xmem_active_file` both carry `#[serde(default)]` from Phase 51. No XROM bit to set. The `v33_save_migrate_after_load_is_idempotent` test confirms this implicitly.

5. **`docs/hp41-xmem-function-matrix.md` must be committed alongside the JSON** — `just docs-matrix-check` in CI will diff them. Run `just docs-matrix` after creating the JSON, before committing both.

6. **X-MEM entries appear in the GUI right panel** — `helpOverlayRows()` in `help_data.ts` filters `key_path !== null`. X-MEM entries have non-null `key_path` values (`"XEQ \"EMDIR\""` etc.), so they appear in the `?` overlay's Extended Memory section. The XROM-exclusion filter in the CLI (`entry.xrom.is_some()` exclusion in `key_ref_entries`) works inversely for X-MEM: `xrom = None` means they pass and appear.
