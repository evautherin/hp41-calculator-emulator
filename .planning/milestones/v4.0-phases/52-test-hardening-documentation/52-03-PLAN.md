<objective>
Extend the two meta-gates so X-MEM op/JSON drift becomes impossible to ship: (1) the op↔JSON parity tests in `function_matrix_parity.rs` (8 `Op` variants ↔ 8 JSON entries, bidirectional) and (2) the per-op test-count floor (≥5 mentions) in `xrom_op_test_count.rs` (D-52.13).

CRITICAL difference from the 5 XROM parity suites: X-MEM ops are HP-41CX OS built-ins resolved by `builtin_card_op()`, NOT `xrom_resolve()`. The reverse parity test MUST call `builtin_card_op(display_name)` — using `xrom_resolve` returns None for all 8 and reports every entry as an orphan (Pitfall 1).

This plan runs in Wave 2: it depends on Plan 01 (the `docs/hp41-xmem-functions.json` pool + `help_entries_xmem()` accessor must exist to compile) and Plan 02 (the 8 `builtin_card_op` arms must exist for the reverse parity test, and the supplementary EmDir/EmRoom/GetD/SaveRx tests must exist BEFORE the ≥5 floor gate activates — Pitfall 4).

Purpose: Drift-proofs X-MEM consistent with the discipline applied to all 5 XROM modules; closes the XMEM-10 meta-gate gap.

Output: X-MEM parity tests + per-op floor extension.
</objective>
