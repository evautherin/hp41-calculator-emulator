<objective>
Execute the operational, cloud-bound acceptance of the phase: create the App Store Connect API
key and add the three GitHub repo secrets (operational prerequisite), trigger a live
`ci-ios.yml` `workflow_dispatch` run to produce + upload a signed IPA, confirm the build in
TestFlight with no ITMS-91053, distribute it to an internal tester group, and verify install on
a real iPhone. This closes SHIP-01, SHIP-02 (cloud confirmation), SHIP-04 (live run), and SHIP-05.

Purpose: These acceptance criteria are inherently manual/cloud-bound — they need live ASC
secrets, the App Store Connect portal, and a physical device. They cannot be automated in CI and
so are gated as human checkpoints.

Output: A distributed internal TestFlight build (no repo files modified).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| founder's ASC account → GitHub repo secrets | The `.p8` and key identifiers are created in App Store Connect and stored as GitHub repo secrets (encrypted at rest). |
| GitHub repo secrets → live CI run | The live workflow run reads the secrets to sign + upload (the runtime exercise of Plan 03's mitigations). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-10 | Information Disclosure | `.p8` downloaded to founder's machine then base64'd | mitigate | Apple allows the `.p8` download once; founder stores it securely and adds only the base64 to GitHub secrets. The local `.p8` is not committed to the repo (it never enters git). |
| T-57-11 | Spoofing/Elevation | Over-privileged ASC API key | accept (documented) | App Manager/Admin requested for reliability of `-allowProvisioningUpdates` (57-RESEARCH Open Q3); least-privilege (Developer-only) can be revisited in a later milestone. Single-app account limits blast radius. |
| T-57-SC | Tampering | npm/pip/cargo installs | n/a | This phase installs no external packages (57-RESEARCH Package Legitimacy Audit: none required). No package legitimacy checkpoint needed. |

(The CI-runtime secret-handling threats T-57-04..09 are owned + mitigated by Plan 03's workflow; this plan exercises them live.)
</threat_model>
