<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub repo secrets → CI runner | The three ASC components cross into the ephemeral macOS runner; the `.p8` is decoded to disk for xcodebuild + altool. |
| CI runner → App Store Connect | The signed IPA + the ASC key authenticate the TestFlight upload over the network. |
| repo → workflow trigger | Who can start the workflow (and thus consume the secrets) — gated to `workflow_dispatch`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-57-04 | Information Disclosure | `.p8` private key leaked to CI logs | mitigate | Never `cat`/echo the key; `base64 --decode` pipes directly to the file; no `set -x` in the write step. Acceptance asserts no stdout pipe of the decoded key. |
| T-57-05 | Information Disclosure | `.p8` persists on runner after a failed run | mitigate | `if: always()` cleanup step `rm -rf`s `~/.appstoreconnect/private_keys/`; GitHub hosted runners are also ephemeral (destroyed post-run). |
| T-57-06 | Information Disclosure | Signing secret over-scoped to whole workflow | mitigate | `APPLE_API_KEY/ISSUER/KEY_PATH` set ONLY in the build step's `env:`, never the global `env:` block. |
| T-57-07 | Spoofing/Elevation | Untrusted contributor triggers the workflow to exfiltrate secrets | mitigate | `workflow_dispatch` only (D-57.4); no PR/push trigger, so no fork PR can run with repo secrets. Manual trigger requires write access. |
| T-57-08 | Tampering | Workflow injection via `github.run_number` in PlistBuddy | accept | `github.run_number` is a numeric integer from the Actions context, not user-controlled input; no injection surface. |
| T-57-09 | Tampering | P12/keychain attack surface on CI | mitigate (by design) | D-57.2 — NO P12/keychain import (ASC API key + `-allowProvisioningUpdates` only). This removes the P-iOS-16 keychain-on-CI failure/attack surface entirely; no `security create-keychain`/`security import` appears in the workflow. |

**Blocking gate:** No HIGH-severity unmitigated threat remains. The two highest-impact risks
(key in logs T-57-04, key persistence T-57-05) are both mitigated with asserted controls.
</threat_model>
