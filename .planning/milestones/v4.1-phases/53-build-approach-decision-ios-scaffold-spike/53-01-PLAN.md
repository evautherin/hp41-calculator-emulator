<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| local shell → Homebrew / rustup | newly-installed CLI tooling (cocoapods, iOS targets) executes with developer privileges |
| `tauri ios init` (cargo-mobile2) → working tree | tool writes generated files into `gen/apple/` |
| working tree → git index | risk of committing generated/secret-adjacent material |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-53-01 | Tampering | `brew install cocoapods`, `rustup target add` | accept | Standard first-party channels (Homebrew formula, rustup component); no third-party package-manager `add` of arbitrary crates; no new runtime deps enter `hp41-core` (zero-new-deps invariant). Low value target, local-only. |
| T-53-02 | Tampering | `tauri ios init` generated `gen/apple/` tree | mitigate | Treat generated tree as opaque; do not hand-edit. gitignore policy task ensures only the `project.yml` source of truth is tracked (or all of `gen/apple/` regeneratable) — no transient `Pods/` or `build/` artifacts committed. |
| T-53-03 | Information disclosure | git index after init | mitigate | No signing material or provisioning secrets exist in this plan (deferred to Plan 04 / Phase 57). Verify `git status` stages no `.p12`, `.mobileprovision`, or `.xcode.env.local` (PATH/secret-adjacent) files. |
| T-53-SC | Tampering | brew/rustup installs | accept | Only first-party toolchain components (CocoaPods via Homebrew, official rustup targets). No npm/pip/cargo dependency additions — RESEARCH confirms zero new runtime deps. No `[ASSUMED]`/`[SUS]` packages → no blocking legitimacy checkpoint required. |
</threat_model>
