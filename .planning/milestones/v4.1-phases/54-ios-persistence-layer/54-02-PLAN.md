## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-54-06 | Denial of Service | repeated visibilitychange firing → save storm | accept | Each save is a cheap clone-then-write (CR-01); WKWebView coalesces visibility transitions; no rate concern for a single autosave file |
| T-54-07 | Tampering | spoofed IPC call to save_state from web context | accept | `save_state` only persists the current in-memory CalcState snapshot — no attacker-controlled data path; the web context is the app's own bundled assets (no remote content) |
| T-54-08 | Information Disclosure | console.warn leaking error detail | accept | Warning goes to the WKWebView console (Xcode/devtools only), not the UI; contains only a serde/IO error string, no secrets |
| T-54-SC | Tampering | npm/pip/cargo installs | mitigate | No new packages; `@tauri-apps/api` already a dep; no install task |

No `high`-severity threats. The MEDIUM-confidence reliability risk (visibilitychange may not fire in iOS WKWebView, RESEARCH Pitfall 4) is a *functional* risk, not a security threat — its safety net is the 30s thread (D-54.2a) and its verification gate is the on-device observation in plan 54-03.
