## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| touch input → overlay div | User touch enters via .key-touch-target; routes through the SAME onKey → dispatch_op IPC path as the desktop SVG click (Rust validates) |
| native iOS → WKWebView | env(safe-area-inset-*) values supplied read-only by the OS |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-55-03 | Tampering | .key-touch-target → onKey | accept | Overlay dispatches the same KeyDef through the existing onKey → dispatch_op path that desktop uses; no new keyId source; Rust key_map::resolve validates identically (RESEARCH §Security Domain V5 partial) |
| T-55-04 | Denial of Service | double-fire from overlay + SVG | mitigate | busyRef dedup retained + SVG onClick skipped when isIos overlay owns dispatch (Pitfall 3) — prevents duplicate IPC calls |

No new high-severity attack surface: this is a presentation/event-model change. Input still flows through the validated desktop IPC path.
</threat_model>
